# Google Photos 재선택과 작업 기록 정리

## 목표

Google Photos 선택·분류를 취소하거나 제출한 뒤에도 같은 창에서 새 선택을 시작할 수 있게 한다. 작업 기록은 사용자가 개별 또는 전체로 삭제할 수 있으며, 삭제 시 앱이 생성한 결과·미리보기와 Google 임시 다운로드도 함께 정리한다.

## Google Photos 화면 상태

| 상태 | 기본 행동 | 보조 행동 |
| --- | --- | --- |
| 연결 전 | Google 계정 연결 | OAuth 설정 |
| 선택 대기 | 선택 링크 열기 | 링크 복사, 선택 취소 |
| 선택 완료 | 선택한 사진 분류 | 화면 초기화 |
| 분류 제출 | 새 사진 선택 | 작업 기록 보기, 화면 초기화 |
| 취소·만료·실패 | 다시 시도 | 화면 초기화 |

분류 제출 화면은 `선택 N개`, `사진 N장`, `동영상 N개 제외`를 구분해 표시한다. Picker에서 동영상이 함께 선택되어도 다운로드와 분석 대상에는 사진만 포함한다.

`화면 초기화`는 현재 Picker URI, session, 임시 화면 요약을 비우고 연결 상태로 돌아간다. 이미 제출된 background job은 중단하지 않으며, 작업 취소는 작업 기록 탭에서 명시적으로 수행한다.

## 작업 기록 삭제

작업 기록 탭은 다음 행동을 제공한다.

- 종료된 작업 상세의 `기록 삭제`
- 상단의 `전체 기록 삭제`
- 삭제 전 macOS 경고 대화상자와 원본 비변경 안내
- 진행 중 작업은 전체 삭제 대상에서 제외

삭제 범위는 다음과 같다.

- 작업 DB의 job, 결과, 검토 선택, 얼굴 검토, checkpoint
- `~/.photos-mcp/runtime/photo-ranker/artifacts/<job-id>` 아래 결과 JSON·preview·face crop
- 해당 job에 임대된 `~/.photos-mcp/cache/google-photos-imports` 임시 파일
- synthetic workflow run과 event

삭제하지 않는 항목은 Apple 사진 원본, 사용자가 고른 로컬 원본, Google Photos 원본·기존 앨범, 사용자가 이미 내보낸 디렉토리와 새 Google 앨범이다. 파일 삭제는 앱 관리 root 내부인지 확인한 뒤에만 수행한다.

## 검증 기준

1. 취소 뒤 `새 선택 시작`과 `화면 초기화`가 활성화된다.
2. 분류 제출 뒤 작업 수와 사진·동영상 제외 수가 일치한다.
3. 개별 삭제는 선택한 종료 작업만 제거한다.
4. 전체 삭제는 완료·실패·취소·재개 확인 필요 기록을 제거하고 진행 중 작업은 유지한다.
5. 작업 artifact와 Google 임시 파일은 사라지지만 관리 root 밖 원본은 유지된다.
6. 기본·최소 창에서 버튼과 요약 문구가 잘리지 않는다.
