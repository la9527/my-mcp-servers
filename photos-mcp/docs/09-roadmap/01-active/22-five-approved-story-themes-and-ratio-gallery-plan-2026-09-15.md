# Story 5종 확장 및 사진 비율 기반 전체 보기 개선안

작성: 2026-09-15 · 최신 상태: 추가 시안 충실도 개선안 재검토, 사용자 컨펌 대기. 아래 과거 구현/승인 기록보다 이 절의 현재 상태를 우선한다.

## 최신 재검토 — 현재 구현과 추가 승인 범위

이번 요청은 5종 모두 제공, 04 공간형의 시안 차이 확인, 05 책형 추가/차별화, 전체 사진의 원본 비율 배치이며 **추가 변경은 컨펌 후 진행**한다. 이번 확인에서는 운영 설정 저장·앱 교체·재분석을 하지 않는다.

### 현재 확인한 사실

- 운영 `http://127.0.0.1:18791/photos` HTML을 다시 조회한 결과 자산은 `v11`, 선택지는 `quiet_memories`, `moment_clusters`, `scroll_cinema`, `spatial_ribbon`, `memory_volume` 5개이며 기본 선택은 `scroll_cinema`다. 아래에 남은 v10/2종 설명은 이전 진단 기록이다.
- 04는 현재 코드에 Swiper 진행률 기반 위치·깊이·회전·반사가 있다. 따라서 현재 구현 전체를 단순 기본 Coverflow라고 설명하는 것은 부정확하다. 그러나 실제 캡처와 04 시안을 비교하면 시안의 넓은 곡면 전시장보다 프레임 안 사진 캐러셀 느낌이 강하다. 특히 첫 사진에서 이전 사진이 없어 왼쪽이 비고, 1278×644의 낮은 창에서 무대와 하단 정보가 한 화면에 들어오지 않는다.
- 05는 `memory_volume`으로 구현되어 있으며 PC 양면·모바일 한 면과 곡면 책장 전환 코드가 있다. 시안처럼 사진과 글의 편집 밀도가 자연스럽게 나오는지는 별개다. 1278×644 캡처에서는 상단 헤더/소개가 공간을 차지하여 책의 하단과 넘김 조작부가 첫 화면 아래로 밀린다.
- 첨부된 전체 목록 오류의 기존 원인은 행 높이와 실제 사진 버튼 높이의 불일치 및 정사각형 파생 이미지의 선행 잘림이었다. 후속 비율 목록 캡처에서는 겹침이 제거된 상태를 확인했다. 이는 모든 설치 환경/기존 공유/Android에서 해결됐다는 의미가 아니다.
- 검토한 실제 캡처: `/tmp/photos-quality-r6-all-1278.png`, `/tmp/photos-quality-r6-spatial_ribbon-1278.png`, `/tmp/photos-quality-r6-memory_volume-1278.png`, `/tmp/photos-review-r4-spatial-pc-middle.png`. 신규 화면을 이번에 재촬영한 것으로 표현하지 않는다.
- 최종 설치본 브라우저 smoke는 완료 증거가 없다. 이전 시도에는 브라우저 자동화 응답 실패가 있어 재검증이 필요하다. Android 실기기 검증도 미완료다.

### 권장 추가 개선

1. **공통 비율 목록을 먼저 확정**: 세로/가로 비율을 보존하는 행 정렬 모자이크를 유지하고 PC 기본 행 높이를 실제 인물 식별이 되는 크기로 조정한다. 날짜/장면 구분과 촬영 순서를 보존하고 사진 실패 안내, 확대 후 같은 위치 복귀, 기존 공유의 비율 이미지 경로를 검증한다. 사진을 다각형으로 자르거나 작은 조각으로 분해하지 않는다.
2. **04 전시장형 화면 구성 보강**: 테마 무대의 가용 높이를 헤더/캡션/조작부를 제외한 viewport에서 계산한다. 중간 사진은 중앙+양옆으로 펼치되 첫/마지막 사진은 균형 있는 별도 끝단 배치를 사용한다. 존재하지 않는 사진 복제나 무한 순환으로 빈 공간을 감추지 않는다. 이웃 사진을 과도하게 어둡게 하지 않고 중앙 사진과 바닥 반사의 간격을 조절한다. 세로 원본을 가로로 잘라 시안의 큰 중앙 프레임을 흉내내지 않는다.
3. **05 사진집 편집 보강**: `memory_volume`을 독립 책형으로 유지한다. 종이/책등/명조의 중성 스타일, 대표 사진+본문+보조 사진 구성을 원본 비율과 글 길이에 맞춰 선택한다. PC에서는 기본 책 펼침과 넘김 조작부가 함께 보이도록 상단 공간을 줄인다. 좁고 낮은 화면에서 글을 지나치게 축소하는 대신 읽기 가능한 단면/스크롤 대체를 제공한다. 다른 테마나 구형 `memory_book` 공유 스타일을 덮어쓰지 않는다.
4. **01/02/03의 독립성 유지**: 01 큰 사진+필름스트립, 02 장면별 비대칭 묶음, 03 세로 이야기 기본값. 5개는 같은 결과 데이터의 서로 다른 감상 방식이며 선택 때문에 LLM 재분석을 실행하지 않는다.
5. **실제 설치본 확인 후 배포**: 1278×644/1440×1000/모바일 세로·가로, 0/1/2/다량 사진, 끝단·긴 글·이미지 실패를 확인한다. 전체 목록 겹침0/비율 유지/스크롤 복귀와 한 장 보기 화면맞춤·Swiper 제스처·지도 접근을 공통 검증한다. 모바일 폭 검사는 Android 실기기 완료로 대체하지 않는다.

컨펌 대상은 **5개 테마 유지 + 공통 모자이크 안정화 + 04 무대/끝단/낮은 창 개선 + 05 편집/화면맞춤 개선 + 설치본 회귀 검증**이다. 기존 개발 변경은 보존하며 추가 구현·배포는 승인 전 보류한다.

## 최신 요청에 대한 확인 결과와 재승인 범위

사용자의 “5개 모두 적용, 04번 원안 차이 확인, 05번 책 추가, 전체 사진 비율 배치 개선, 컨펌 후 진행” 요청에 대한 현황이다. 아래 과거 승인·개발 기록과 현재 설치본을 구분한다.

- **운영 설치본**: `http://127.0.0.1:18791/photos`를 읽기 전용 확인한 결과 CSS/JS `v=10`, 선택 항목은 `scroll_cinema`, `spatial_ribbon` 두 개다. 5종이 이미 운영 반영된 상태가 아니다.
- **개발 미리보기**: 별도 loopback 18809에 신규 5종과 비율 목록 변경이 존재한다. 미커밋 개발 내용이며, 설치본 배포·서비스 교체·사용자 Story 설정 저장은 이번 재검토에서 수행하지 않았다.
- **04 원안 차이**: 운영본은 장면마다 배치된 얕은 Coverflow다. 시안의 화면 전체 곡선 무대, 넓은 중앙 사진, 좌우 여러 장의 깊이와 바닥 음영, 장면 타임라인을 완성한 상태가 아니다. 개발안도 혼합 비율에서 중앙 폭과 모바일 선명도를 최종 점검해야 한다.
- **05 원안 차이**: 개발안에는 양면 책·모바일 한 면·곡면 책장 전환이 있으나 운영본에는 없다. 실제 자료는 날짜 제목·추천 요약이 많아 시안의 풍부한 이야기와 편집 밀도가 자동으로 재현되지는 않는다. 사진 비율별 편집 템플릿, 긴 글의 페이지 분할, 불필요한 여백을 따로 검증한다. 이름·위치·사건을 디자인용으로 지어내지 않는다.
- **전체 사진 문제**: 행 높이보다 사진 버튼이 커지는 겹침과 정사각형으로 이미 잘린 썸네일이라는 두 층의 문제다. CSS만 바꾸면 이미 잘린 원본 영역이 복구되지 않으므로, 방향 보정·비율 보존 `gallery` 파생 이미지와 행 정렬형 비율 배치를 함께 적용한다. 기존 정사각형 썸네일 용도는 유지한다.

권장 재승인 범위는 **03 기본 유지 + 01~05 모두 독립 선택 + 공통 비율 목록 + 공통 확대 뷰어**다. 감상 테마는 색상만 바꾸지 않고 화면 구조와 조작 방식으로 구분한다. 05의 종이색·명조·책등 표현은 테마 내부에만 적용하고 다른 화면을 책 스타일로 바꾸지 않는다.

진행 순서는 **전체 사진 비율/겹침 → 05 책 편집 → 04 공간 무대 → 01/02 독립 감상 → 통합 검증·배포**를 권장한다. 단계마다 실제 사진의 PC·모바일 캡처를 기준으로 확인하며, 라이브러리 초기화나 자동 테스트 통과만으로 원안 충실도 완료를 선언하지 않는다.

현재 미리보기의 검증 기록은 운영 완료 근거가 아니다. 전체 자동 검사 1,097개 통과와 문서 명명/인덱스 1개 실패가 있었다. 문서 경로 교정 후 문서 구조 검사 2개는 통과했으며 전체 재실행은 아직 하지 않았다. 실기기 Android 검증도 별도 미완료 상태다.

모바일 전체 목록 캡처에서는 겹침이 사라져도 390px 화면에 4~5장이 한 행에 놓여 인물 식별이 작게 보인다. 승인 후 기본 밀도를 낮춰 일반 사진은 2~3장 수준을 우선하고, 사진의 실제 비율에 따라 행별 개수를 유연하게 조정한다. 작은 썸네일을 많이 표시한 것을 디자인 완료로 판단하지 않는다.

04번 최신 미리보기 재검토에서도 중앙·이웃 사진이 안쪽으로 쌓이는 문제가 남았다. 390px에서 이전 사진 x70~219, 중앙 x75~315, 다음 x171~320으로 이웃이 중앙 뒤에 대부분 포개진다. Swiper 진행 방향과 전용 바깥 이동 변환의 부호를 맞추는 것이 우선이며, 이후 중앙/이웃의 노출 폭을 캡처로 검증한다. PC의 넓은 리본과 모바일 중앙+양옆 일부가 보이는 구성이 모두 충족되기 전에는 04번 원안 반영 완료로 보지 않는다. 단일 장면에서는 날짜 캡션과 타임라인 중복도 제거할 계획이다. 이 진단 이후 추가 코드 수정은 컨펌 대기로 보류했다.

## 승인된 품질 상향 (기존 제약을 대체)

사용자는 물리적 디테일을 포함한 원안 충실도와 실제 화면 품질을 명시적으로 요구했다. 따라서 아래의 평면/얕은 회전만을 권장했던 05번 제한은 폐기하고 **구간별 곡면으로 휘어지는 종이, 앞뒷면, 책등, 종이 층과 움직이는 음영**까지 구현한다. 04번도 기본 Coverflow가 아닌 실제 공간 배치·깊이·타임라인을 구현한다. 스크롤 시네마 기본 유지, 5종 모두 선택 가능은 필수다.

3개 구현/검토 에이전트: 책의 물리 표현, 공간형 충실도, 비율 목록·01/02 UX. 모두 PC·모바일 실제 캡처를 보고 독립적으로 3차례 이상 검토한다. 각 회차는 화면 증거 → 문제 지적 → 수정 → 새 캡처로 구분한다. 코드 읽기나 동일 캡처 재사용은 새 회차로 계산하지 않는다. 자동 테스트와 시각 품질은 별도의 완료 조건이다.

실제 Android 기기는 현재 ADB 미연결이며 사용자에게 연결을 요청했다. 모바일 브라우저 폭 검사와 Android 실기기 검증을 구분하고 실기기 증거가 없으면 전체 완료라고 표시하지 않는다.

## 1. 범위와 현재 상태

이번 5종은 `.planning/sketches/003-story-ux-reset/`의 고요한 추억 / 순간의 묶음 / 스크롤 시네마 / 공간을 흐르는 사진 / 펼쳐보는 기억의 책이다. 과거 코발트 포스터 등 5개 테마와 혼동하지 않는다.

현재 선택 가능한 것은 `scroll_cinema`, `spatial_ribbon` 2개뿐이다. 고요한 추억은 공통 확대 뷰어로 일부 구현됐지만 독립 Story 테마는 아니며, 순간의 묶음과 기억의 책은 미구현이다. 기본 스크롤 시네마는 유지하고 5종 모두 독립 감상 방식으로 제공하는 것이 이번 권장 목표다.

## 2. 전체 사진 화면 오류 — 재현된 원인

1278×644 Chromium, 운영 Story 315장, 상단 `전체 사진`으로 직접 진입하여 재현했다.

- `.viewer-all-grid`는 CSS Grid이며 사진 버튼은 `aspect-ratio:1`, 이미지 높이는 `100%`다.
- 실제 버튼은 166.56×166.56px인데, 암시적 grid row는 48px로 계산됐다.
- 첫 행 버튼 위쪽 84px / 아래쪽 250.56px, 다음 행 위쪽 144px: 약 106.56px가 겹친다.
- 기본 버튼 `min-height:48px`와 퍼센트 이미지 높이·비율 기반 높이를 행 크기로 환산하는 단계가 맞지 않는다. 단순히 object-fit이 잘못된 문제가 아니다.
- 격리 브라우저에서만 버튼 높이를 측정 너비로 명시하는 임시 진단을 수행했다. 행 높이가 166.58px, 다음 행 시작이 262.58px로 바뀌어 겹침이 사라졌다. 새로고침으로 이 임시 DOM 변경을 폐기했다.
- 제품 코드나 운영 CSS는 수정하지 않았다.

지난 검증은 목록 장수·열기·선택을 검사했지만, 사진 간 사각형 겹침과 클릭 가림을 검사하지 않아 놓쳤다. 새 검증은 기하학적 무결성을 필수 gate로 추가한다.

## 3. 전체 사진은 원본 비율 모자이크로

권장: 원본 비율을 보존하는 행 정렬형 모자이크(Justified Gallery). 모든 사진을 정사각형으로 만들거나 퍼즐 모양으로 잘라내는 방식은 아니다.

- 세로 사진은 좁고 길게, 가로 사진은 넓게, 파노라마는 넓은 한 줄 등으로 보여준다.
- 한 행의 높이를 맞추되 개별 사진 폭은 사진 비율에 따라 다르게 계산한다.
- 사진은 비율 그대로 표시하여 얼굴·풍경을 기본적으로 자르지 않는다.
- 순서는 촬영 시간/현재 Story 순서대로 좌→우, 위→아래로 유지한다. 단순 CSS 다단 Masonry처럼 위→아래 열 우선 순서로 바꾸지 않는다.
- 날짜/장면 단위로 묶고 마지막 행에 사진이 적으면 왼쪽에 배치한다. 남은 1장을 화면 전체로 과하게 확대하지 않는다.
- 초기 목표 행 높이: PC 약 180–240px, 모바일 약 120–180px. 실제 혼합 비율 표본으로 확정한다.
- 버튼과 이미지의 크기를 계산 결과로 명시하여 row/button/image의 높이가 달라지지 않게 한다.
- 목록 컨테이너만 세로 스크롤하고 상단의 `사진으로 돌아가기`·`닫기`는 고정한다.
- 315/1,000장에서는 이미지 지연 로딩과 가까운 묶음 우선 렌더링을 사용한다. 키보드 탐색과 목록 순서를 잃는 가상화는 성능 측정 없이 도입하지 않는다.
- 선택 사진의 asset ID·그룹·스크롤 위치를 저장하여 큰 사진에서 돌아오면 같은 위치로 복귀한다.

Flickr의 justified-layout처럼 비율 목록으로 좌표·크기를 계산하는 모델이 적합하다. 라이브러리 사용 여부는 라이선스·번들 크기·유지보수 검토 후 확정하고 로컬 번들로 제공한다. CSS 기본 masonry의 기기별 지원에 의존하지 않는다.

## 4. 5개 테마를 구분하는 기준

| 테마 | 현재 | 승인 후 구성 | 핵심 탐색 |
|---|---|---|---|
| 01 고요한 추억 | 공통 뷰어에 일부 구현 | 독립 사진 감상 화면, 큰 사진 1장, 짧은 장면 설명, 하단 필름스트립 | 좌우 이동·썸네일 |
| 02 순간의 묶음 | 미구현 | 날짜/장면별 대표 사진과 서로 다른 비율의 사진 묶음, 비대칭 편집 | 세로 탐색 → 장면/사진 선택 |
| 03 스크롤 시네마 | 구현 | 현재 기본 유지, 사진 비율·정보 접근·일관성 보완 | 일반 세로 스크롤 |
| 04 공간을 흐르는 사진 | 단순화된 구현 | 화면 중심의 넓은 곡선 사진 무대, 장면 타임라인, 선택 사진 정보 | 드래그·장면 점프 |
| 05 펼쳐보는 기억의 책 | 미구현 | 종이색 사진집, PC 양면/모바일 한 면, 목차·페이지 전환 | 책장/목차 → 사진 확대 |

같은 페이지의 색깔만 바꾸지 않는다. 사진 이동 방식·장면 구성·공간 구조가 실제로 달라야 한다. 내용과 개인 정보 정책은 공통이며 테마 변경 때문에 재분석/LLM 재호출은 하지 않는다.

## 5. 04번 시안과 구현의 차이 및 보완

현재 코드: 각 `[data-theme-gallery]`마다 별도 Swiper 생성, `effect:coverflow`, rotate PC14°/mobile8°, depth110, 중앙 사진 폭 PC65%/mobile80%, shadow 비활성. 원근 효과 자체는 있으나 넓은 공간형 Story가 아닌 작은 장면별 캐러셀이다.

| 시안의 특징 | 현재 | 수정 방향 |
|---|---|---|
| 화면을 크게 쓰는 공간 무대 | 본문 안 장면별 작은 캐러셀 | 화면 맞춤 공간 무대 하나 + 장면 점프 |
| 중앙과 양쪽 사진이 곡선으로 펼쳐짐 | 큰 중앙 사진과 일부 이웃만 보임 | 충분한 사진이 있을 때 PC 약5–7장, 모바일 중앙+양옆 일부 |
| 앞뒤 거리·바닥 깊이감 | 기본 Coverflow 원근만 존재 | 거리별 크기·회전·위치와 약한 바닥 음영 |
| 도착/산책/노을 같은 장면 타임라인 | 이전/다음·장수만 표시 | 실제 장면 이름·날짜 기반 타임라인 |
| 선택 사진이 정면 감상으로 연결 | 공통 뷰어로 열림 | 유지하되 선택 위치와 복귀 위치 보존 |

Swiper는 입력·관성·인덱스 관리에 계속 사용한다. 시안과 가까운 곡선은 slide progress 기반 전용 transform 계층으로 구현하며 Swiper 본체 transform과 충돌하지 않게 wrapper를 분리한다. 기본 Coverflow 설정값 변경만으로 시안과 동일하다고 하지 않는다. Three.js/WebGL은 이 범위의 필수 조건이 아니다.

자동 카메라 비행·사진 내부 깊이 생성은 제외한다. 모션 감소/성능 저하 시 명시적으로 평면 모드로 전환하되 같은 사진 위치·장면 정보를 보존한다. 부족한 사진을 복제해 7장으로 채우지 않는다.

## 6. 05번 기억의 책 구현 방향

- PC: 왼쪽 큰 사진, 오른쪽 제목·이야기·보조 사진을 놓는 양면 구성. 사진 비율/장수에 따라 대표 사진 1장, 세로 2장, 가로 1장+설명 등의 제한된 템플릿을 선택한다.
- 모바일: 양면을 축소하지 않고 한 페이지씩 보여준다. 논리적 페이지 ID를 유지해 화면 회전 시 동일 내용을 잃지 않는다.
- 중성 아이보리·종이 질감·얕은 책등과 그림자로 사진집 느낌을 만든다. 밝은 장식색·스티커 중심의 예전 팝업 플레이북과 구분한다.
- 얼굴과 사진을 중앙 접힘선 위에 걸치지 않는다. 종이 영역 밖으로 이미지가 넘치거나 본문이 잘리지 않게 한다.
- 장면별 기존 문구를 사용하고 긴 글은 다음 페이지로 나눈다. 사진·사람 이름·장소를 임의 생성하지 않는다.
- 목차, 이전/다음, 페이지 번호를 제공하고 사진 클릭은 공통 평면 뷰어로 연결한다.
- 전환은 구간별 곡면 종이 모델을 사용해 실제 휘어지는 페이지와 앞뒷면, 진행도에 따른 음영을 표현한다. 평면 flip으로 대체하지 않는다. 책장 중간 진행도·역방향 넘김·손을 놓았을 때 복귀/완료 동작까지 캡처와 동작 검사로 검증한다.
- 모션 감소 시 평면 전환. 페이지 넘김과 확대 제스처는 각각 책 화면/공통 뷰어로 분리한다.

## 7. 공통 기술 구조

```text
기존 Story / 사진 / 인물 / 위치 데이터
                ↓
공통 photo view model (asset ID, 방향 보정된 width/height, 순서)
                ↓
선택한 5개 테마 renderer + 테마별 상태
                ↓
전체 사진 비율 모자이크 ⇄ 공통 평면 확대 뷰어
```

- 화면 구조가 다른 테마를 CSS selector로만 덮어씌우지 않는다. renderer/controller를 분리하고 활성 테마만 초기화한다.
- 테마 전환 시 Swiper·이벤트·observer를 정리하고 사진 선택·장면 위치를 유지한다.
- 사진 비율은 EXIF 방향이 반영된 파생 이미지 치수로 전달한다. 기존 Story에 치수가 없으면 캐시된 파생 이미지 메타데이터를 읽어 보충한다. GPS/원본 EXIF를 공유에 추가할 필요는 없다.
- 치수 보충은 얼굴·비전 재분석이 아니다. lazy 이미지가 모두 로드돼야 레이아웃이 안정되는 구조를 피한다.
- 01/02/05는 새 theme ID를 부여한다. 기존 `memory_book`은 구형 팝업 플레이북이므로 재사용하여 과거 공유 의미를 덮어쓰지 않는다.
- 기존 공유 스냅샷의 선택 테마 보존. 신규 5종 선택은 Mac·Android·새 공유에 같은 의미로 적용한다.
- 서버 공통 웹 콘텐츠 변경이 중심이다. Android native 변경이 필요해질 때만 APK 범위를 별도로 명시한다.

## 8. 승인 후 순서와 완료 기준

1. **공통 목록 오류 및 비율 모자이크 우선**: 스크린샷 케이스 재현 테스트 → 겹침 제거 → 비율 보존 목록.
2. **기억의 책**: PC 양면·모바일 한 면 실제 사진 프로토타입 → 목차·페이지 전환·뷰어 연결.
3. **공간형 시안 충실도 보강**: 넓은 무대·곡선 배치·장면 타임라인·모션 대체.
4. **01/02 독립 테마 추가**: 큰 사진 중심 감상과 장면별 비대칭 묶음의 차별화.
5. **5종 통합**: 미리보기·스타일 적용·재접속 유지·기존 공유 호환·Mac 설치본/모바일 서비스 검증.

필수 검증:

- 사진 수 0/1/2/7/315/1,000, PC 1278×644·1440×1000, 모바일390×844·가로844×390.
- 세로/가로/정사각/파노라마/긴 캡처·치수 없음·이미지 실패·긴 설명.
- 모자이크: 각 사진 사각형 간 면적 겹침 0, 중앙 지점 hit-test가 해당 버튼, 이미지/컨테이너 비율 일치, 마지막 행·화면 회전 후 안정성.
- 큰 사진 맞춤·확대·다음 사진 배율 초기화·드래그·터치·키보드·뒤로가기·원래 위치 복귀.
- 인물 필터·날짜/장면 이동 후 본문과 뷰어가 같은 사진 집합·순서를 사용.
- 5종 반복 전환 시 DOM/Swiper 중첩·핸들러 누적 없음, 숨긴 테마 전체 사진 중복 다운로드 없음.
- 실제 스크린샷으로 디자인 시안과 비교하고 차이를 기록. 라이브러리 초기화 성공을 디자인 완성으로 간주하지 않음.
- Android/WebView 실기기 검증 가능 여부를 별도로 기록하고 모바일 폭 검사와 구분.

## 9. 디자인 감사 메모

refactoring-ui의 8개 항목 중 현 전체 사진 목록은 5개 충족으로 **6/10**(이 화면에 한정한 정성 평가).
통과: 무채색, 라벨 우선순위, 텍스트 폭, 기본 글자 대비, 과도한 그림자 없음.
개선: 사진의 시각적 위계, 실제 사진 사이 여백/겹침, 일관된 간격 체계. 원본 비율·정돈된 간격·장면 구분을 우선하며, 색 추가로 덮지 않는다. 이 점수는 렌더링 버그의 심각도를 낮추는 근거가 아니다.
