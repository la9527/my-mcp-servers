# 유사 장면 대표 2장과 개인 취향 추천 강화 계획

- 작성일: 2026-08-03
- 최종 재검토: 2026-08-03 (Apple Vision 및 최신 로컬 이미지 품질·개인화 연구 반영)
- 상태: Phase 1 구현·50장 실사진 검증 완료, Phase 1.5 사전 런타임 및 새 Apple 사진 1,000장 종단 재검증 완료, 추천 로직 변경은 미착수
- 대상: `photo-ranker`, Apple 사진 읽기 계층, 사진 분류 결과 갤러리
- 전제: 사용자가 말한 `히트가 표기된 사진`은 Apple 사진의 하트, 즉 즐겨찾기로 해석한다.

## 1. 결론

현재 문제는 하나의 점수 공식을 조정하는 것만으로 해결하기 어렵다. 다음 두 판단을 분리해야 한다.

1. **장면 안 선택**: 같은 인물과 배경으로 연속 촬영한 사진을 하나의 촬영 묶음으로 만들고, 묶음마다 잘 나온 사진을 최대 2장만 추천한다.
2. **장면 간 개인화**: 여러 촬영 묶음 중 사용자가 평소 선호하는 사진 유형을 즐겨찾기와 명시적 피드백에서 학습해 추천 순서를 보정한다.

우선순위는 장면 묶음과 대표 2장 선택이 먼저다. 개인 취향 모델부터 적용하면 같은 장면의 사진들이 모두 비슷한 높은 취향 점수를 받아 중복 추천 문제가 오히려 유지될 수 있다.

권장 기본 동작은 `묶음마다 최대 2장`이다. 사진이 2장 있다고 무조건 2장을 추천하지는 않는다. 두 번째 사진이 품질 기준을 통과하지 못하거나 첫 번째와 사실상 동일하면 1장만 추천한다.

Phase 1 다음에는 개인화 모델을 바로 만들지 않고 **Phase 1.5 품질·평가 강화**를 먼저 수행한다. 현재 50장 검증은 기능 동작을 확인하기에는 충분하지만 다양한 촬영 조건에서 장면 경계와 베스트 2장 품질을 확정하기에는 작다. Phase 1.5에서 다음 기반을 먼저 고정한다.

1. 완전 중복과 시각적 근접 중복을 분리한다.
2. Vision FeaturePrint와 폴백 특징의 버전·거리 기준을 분리한다.
3. Apple Vision 얼굴 촬영 품질과 선택적 미학 점수를 후보 압축에 추가한다.
4. 여러 시기와 사진 유형을 포함한 200~300개 장면 정답 세트를 만든다.
5. 후보 4장 압축이 실제 베스트 사진을 보존하는지 `Recall@4`로 검증한다.

개인화도 한 모델로 합치지 않는다. **장면 내부 베스트 사진 선택 모델**과 **장면 간 사용자 관심도 모델**을 분리한다. 즐겨찾기는 추억·인물·행사의 중요도를 강하게 포함할 수 있으므로 사진 자체의 기술 품질 정답으로 간주하지 않는다.

### Phase 1 적용 결과

2026-08-03에 개인화 없이 장면별 최대 2장을 선택하는 Phase 1을 제품 기본 경로에 적용했다.

- Apple 촬영 시각, 연사 관계, 인물 집합과 macOS Vision `VNGenerateImageFeaturePrintRequest` 특징을 결합한다.
- 일반 시각 거리 기준은 `0.08`, 동일 인물이 확인된 경우의 완화 기준은 `0.10`으로 정했다.
- 일반 촬영은 기존 묶음과 새 후보의 가장 가까운 촬영 간격을 120초 이내로 제한한다. 동일 인물이 확인되면 이 간격을 최대 300초까지 완화하되, 두 경우 모두 최종 묶음 전체의 촬영 시간 폭은 300초를 넘기지 않는다.
- 서로 다른 장면이 연쇄적으로 합쳐지지 않도록 새 후보와 기존 묶음의 모든 교차 거리를 검사한다.
- pHash 근접 중복 묶음의 대표는 입력 순서가 아니라 기술 품질 점수로 선택한다.
- 장면마다 상세 VLM 후보를 최대 4장으로 압축하고, 최종 추천은 최대 2장으로 제한한다.
- 두 번째 추천도 전역 품질 하한을 통과해야 하며, 첫 번째와 사실상 동일하면 제외한다.
- 결과 DB와 공개 결과에 묶음 ID·크기·순위·추천 슬롯·선택 이유를 저장하고 갤러리와 Inspector에 표시한다.

초기 계획의 OpenCLIP 재사용 대신 macOS Vision FeaturePrint를 선택했다. 현재 앱 번들에서 이미 사용하는 Apple 프레임워크와 결합하기 쉽고, 모델 파일을 별도로 내려받지 않으며, 모든 특징 계산을 Mac 안에서 수행할 수 있기 때문이다.

다만 Vision을 사용할 수 없는 개발 환경의 결정적 16×16 RGB 특징은 Vision FeaturePrint와 표현 공간과 거리 분포가 다르다. 따라서 같은 거리 임계값과 같은 알고리즘 버전을 공유해서는 안 된다. Phase 1.5에서는 다음 중 하나를 적용한다.

- 제품 경로에서는 Vision 특징 생성 실패 시 자동 장면 병합을 중단하고 시간·연사 관계만 사용한다.
- 테스트 폴백이 필요하면 `rgb-thumbnail-v1`처럼 별도 백엔드 ID, 캐시 버전과 검증된 별도 임계값을 사용한다.
- Vision 요청 revision과 macOS 버전을 특징 캐시 키와 알고리즘 진단 정보에 포함한다.

50장 실사진 검증 결과는 다음과 같다.

| 항목 | Phase 1 결과 |
| --- | ---: |
| 입력 사진 | 50장 |
| 장면 묶음 | 13개 |
| 여러 사진이 포함된 장면 | 7개 |
| 가장 큰 장면 | 15장 |
| 장면별 상세 후보 상한 | 4장 |
| VLM 상세 분석 후보 | 32장 |
| 최종 추천·선택 | 14장 |
| 장면당 추천 상한 위반 | 0건 |
| 전체 회귀 테스트 | 306개 통과 |

첫 실운영 검증에서는 동일 인물 완화 거리 `0.16`이 최대 23장을 하나로 묶는 과병합을 일으켰다. 이를 `0.10`으로 낮춘 후 최종 설치 앱의 512px 분석 입력에서는 최대 묶음이 15장으로 줄었다. 결과 화면에서 이 15장은 같은 튤립 화단과 산책로 배경의 연속 촬영임을 확인했고, 추천 2장과 나머지 대안 사진으로 정상 표시됐다. 더 큰 정답 세트에서는 경계 사례를 포함해 precision·recall을 추가 측정해야 한다.

### Phase 1.5 사전 런타임 실험

2026-08-03에 위 50장 결과의 로컬 미리보기로 macOS Vision API를 직접 실행했다. FeaturePrint revision 2는 768개 float32 요소를 반환했고, 1,225개 사진 쌍에서 Apple 공식 거리와 현재 raw 코사인 거리의 순위 상관은 `0.999997`이었다. 이 표본의 현재 장면 ID에 맞춘 분포 매핑에서는 raw 코사인 `0.076619`, 공식 거리 `0.391545`가 같은 대리 F1 `0.753056`을 만들었다. 이는 두 거리의 **순위·분포가 유사함**을 보여 줄 뿐, 사람 정답에 대한 장면 품질 우위를 의미하지는 않는다.

`VNDetectFaceCaptureQualityRequest`는 50장 중 47장에서 총 95개 얼굴 품질을 반환했고, `VNCalculateImageAestheticsScoresRequest`는 50장 모두에서 관측값을 반환했다. 하지만 `isUtility=true`는 0장이어서 미학 API를 곧바로 추천 점수에 넣을 근거는 없다. 세 요청의 중앙 시간은 각각 약 5.53ms, 7.11ms, 5.93ms로 후보 압축 전의 shadow 계측에는 적합했다.

가장 중요한 사전 검토 결과는 현재 결과 계약에 사진별 `detail_candidate`와 후보 순위가 없어 `Recall@4`를 사후 산출할 수 없다는 점이다. Phase 1.5의 첫 변경은 점수 가중치가 아니라 이 계측 필드, 특징 백엔드·거리 방식·request revision·알고리즘 버전의 저장이다. 상세 결과와 재현 명령은 `experiments/phase1_5_preflight_2026-08-03/`에 분리해 기록했다.

### 새 Apple 사진 100장 재검증

기존 50장 결과와 겹치지 않도록 Apple 사진 보관함에서 새 100장을 로컬 전용 검증 세트로 만들었다. 20개 시간 인접 세션에서 세션당 최대 5장을 선택했고, 원본·미리보기·사진 ID·개별 분석은 `$HOME/.photos-mcp/validation/` 밖으로 내보내지 않았다. 제품과 같은 `select_best`, 상위 30% 정책으로 현재 파이프라인을 실행한 결과는 다음과 같다.

| 항목 | 결과 |
| --- | ---: |
| 장면 묶음 | 83개 |
| 다중 사진 장면 | 12개 |
| 최대 장면 크기 | 5장 |
| VLM 상세 분석 | 99장 |
| 최종 추천 | 27장, 23개 장면 |
| 장면당 추천 상한 위반 | 0건 |
| 종단 실행 시간 | 420.61초 |

이번 실행은 PyObjC Vision을 executor 작업 스레드에서 동시 import하여 `VNGenerateImageFeaturePrintRequest`가 부분 초기화되던 문제를 수정한 뒤 수행했다. 재검증 중 RGB thumbnail 폴백 경고 없이 FeaturePrint 경로가 실행됐다.

후속 검증을 위해 기존 50장, 100장 및 중단된 500장 준비 세트와 겹치지 않는 1,000장 Apple 사진 세트도 별도 개인 경로에 준비했다. 200개 시간 인접 세션에서 세션당 최대 5장을 선택했으며, 세 기존 세트와 사진 ID 교집합은 모두 0장이다. 이 세트의 전체 VLM 종단 실행은 약 70분 이상이 걸리므로, 실행 결과와 사람 검토 라벨은 별도 기록으로 추가한다.

한계도 명확하다. 현재 Python 환경에는 기존 `FaceEngine`이 요구하는 얼굴 검출 백엔드가 없어 모든 `faces_detected`가 0이었다. 따라서 이 결과는 시각적 군집, VLM 상세 분석과 장면별 최대 2장 정책의 동작 재검증이며, 얼굴 기반 완화 규칙이나 얼굴 촬영 품질의 추천 이득을 입증하지 않는다. 또 후보 여부·후보 순위 필드와 사람 검토 정답이 없으므로 `Recall@4`, 장면 F1, Top-2 정확도는 여전히 측정 불가다.

### 1,000장 종단 재검증과 운영 안정성

기존 50장, 100장 및 준비만 한 500장 세트와 중복되지 않는 Apple 사진 1,000장도 200개 시간 인접 세션으로 구성해 실행했다. 776개 장면 중 150개가 다중 사진 장면이었고 최대 장면 크기는 8장이었다. VLM 상세 분석은 986장, 최종 추천은 293장(266개 장면), 두 장 추천 장면은 27개였으며 장면당 2장 상한 위반은 없었다. 총 실행 시간은 3,880.91초(64분 41초)다.

첫 실행은 Linux의 30분 유휴 종료가 VLM 서버를 끄며 실패했다. 이후 원격 VLM 응답이 성공할 때마다 활동 시각을 기록하고, 개인 데이터셋 경로에 사진 단위 filter/VLM SQLite 체크포인트를 남기도록 변경했다. 재실행은 30분을 넘어도 종료되지 않았고 끝까지 완료됐다. 이 변경은 장시간 실사용 작업에도 필요하지만, 개인 체크포인트에는 사진 ID와 분석 스냅샷이 들어가므로 Git이나 공유 경로에 저장하지 않는다.

더 넓은 표본에서도 현재 이벤트 분류 결과는 `travel`이 257장으로 집중됐다. 이는 보관함의 실제 구성일 수도 있으나 현재 프롬프트의 travel 우선 규칙으로 인한 편향일 가능성도 있다. 따라서 다음 단계는 개인화나 가중치 변경이 아니라, 유형 균형을 맞춘 사람 검토 정답 세트에서 이벤트 분류·장면 경계·Top-2를 분리 평가하는 것이다.

### 사람 검토 정답 세트 준비

1,000장 재검증 결과에서 다중 사진 장면을 우선 포함하고 시간축으로 분산한 단일 장면을 추가해 250개 장면 검토 대기열을 만든다. 대기열에는 현재 묶음, 장면 안 후보 순위·추천 상태와 사진 미리보기 참조만 포함한다. 사람이 `scene_boundary`, `best_photo_ids`(0~2장), `second_recommendation`, `event_type`, `failure_codes`와 자유 메모를 기록한다.

이 정답 세트와 지침은 `$HOME/.photos-mcp/validation/`의 개인 경로에만 생성한다. 사진 ID·미리보기·자유 텍스트가 포함되므로 저장소에는 검토 생성 스크립트와 비식별 집계만 남긴다. 첫 라벨링 후 다음 도구에서 후보 `Recall@4`, Top-1, Recall@2, NDCG@2, 장면 과병합·과분할률과 이벤트 분류 혼동 행렬을 계산한다.

후속 실행 결과에는 `detail_candidate`와 `detail_candidate_rank`을 기록한다. 이 값으로 “사람이 고른 베스트 사진이 장면당 상세 후보 4장 안에 남았는지”를 계산할 수 있다. 기존 1,000장 결과는 이 계약 이전에 생성돼 해당 필드가 없으므로, 라벨 측정용 실행은 새 계약으로 다시 수행하거나 기존 결과를 재생성해야 한다.

## 2. Phase 1 이전 구현에서 확인한 원인

Phase 1 이전 `photo-ranker`에는 pHash 기반 중복 제거만 있었다.

- `DedupEngine`은 DCT 기반 pHash와 Hamming distance 기본 임계값 8을 사용한다.
- 중복 묶음의 대표 사진은 품질 비교 결과가 아니라 입력 순서의 첫 사진이다.
- 대표 사진이 아닌 항목은 `passed_stage1=False`가 되어 VLM 분석 전에 제외된다.
- pHash 중복이 아닌 사진은 전체 점수순으로 각각 추천될 수 있다.
- 결과 UI는 `selected` 또는 종합 점수 80 이상을 모두 추천으로 표시한다.

이 구조는 같은 파일의 복사본이나 변화가 매우 작은 사진에는 유효하지만 다음 상황을 하나의 장면으로 보지 못할 수 있다.

- 같은 위치에서 인물의 표정이나 자세만 달라진 연속 촬영
- 카메라가 조금 이동하거나 줌이 달라진 사진
- 인물은 같지만 배경 일부가 가려지거나 구도가 바뀐 사진
- Live Photo, 일반 연속 촬영과 Apple 연사가 섞인 경우
- 같은 장면을 RAW와 JPEG 또는 편집본으로 보관한 경우

따라서 `파일 중복`과 `촬영 장면 유사성`을 서로 다른 계층으로 다뤄야 한다.

## 3. 현재 보관함 신호의 가용성

설치 환경의 Apple 사진 보관함을 원본 내용이나 이름을 노출하지 않고 집계한 결과는 다음과 같다.

| 항목 | 수량 | 전체 사진 대비 |
| --- | ---: | ---: |
| 사진 | 21,786장 | 100% |
| 즐겨찾기 | 486장 | 2.23% |
| Apple 연사 사진 | 178장 | 0.82% |
| 연사에서 사용자가 선택한 사진 | 1장 | - |
| 편집 이력이 있는 사진 | 508장 | 2.33% |

현재 설치된 `osxphotos 0.75.9`는 다음 값을 읽기 전용으로 제공한다.

- `favorite`
- `burst`, `burst_selected`, `burst_key`, `burst_default_pick`, `burst_photos`
- `hasadjustments`
- 촬영 시각, 앨범, 인물, 키워드, GPS와 EXIF

그러나 Photos MCP의 현재 `Photo`와 `PhotoMetadata` 계약에는 즐겨찾기, 연사 선택과 편집 여부가 포함되어 있지 않다. 개인화 전에 이 값을 내부 학습 신호 계약으로 추가해야 한다.

즐겨찾기 486장은 개인화 가능성을 검토하기에는 충분하지만, 전체의 2.23%에 불과해 일반적인 이진 분류로 학습하면 안 된다. 즐겨찾기가 아닌 사진은 `싫어함`이 아니라 대부분 `아직 표시하지 않음`이므로 **양성-미표기 학습(positive-unlabeled learning)** 문제로 취급해야 한다.

공개 결과에는 얼굴 임베딩, 원본 경로, 즐겨찾기 학습 원본과 인물 이름을 넣지 않는다. UI에 필요한 안정적인 묶음 ID, 묶음 내 순위, 추천 여부와 설명 코드만 노출한다.

## 5. 유사 촬영 장면 묶음 설계

### 5.1 세 단계의 유사성

| 단계 | 목적 | 권장 신호 |
| --- | --- | --- |
| 완전 중복 | 바이트가 동일한 복사본 제거 | checksum, Apple 자산 관계 |
| 근접 중복·파생본 | 리사이즈, 편집본, RAW/JPEG 등 시각적으로 거의 같은 사진 연결 | pHash, 자산 파생 관계, 촬영 메타데이터 |
| 연사 묶음 | Apple이 이미 알고 있는 연사 복원 | `burst_photos`, `burst_selected`, `burst_default_pick` |
| 촬영 장면 묶음 | 같은 배경·인물·순간의 연속 촬영 연결 | 시간, 시각 임베딩, 인물 집합, GPS, 카메라 정보 |

Apple 연사 정보가 있으면 이를 최우선 경계로 사용한다. 일반 연속 촬영은 촬영 시각으로 후보 구간을 먼저 만든 후 시각 유사성으로 나눈다.

### 5.2 권장 클러스터링 절차

1. 촬영 시각순으로 정렬하고 일정 시간 간격 안의 사진만 비교 후보로 만든다.
2. checksum으로 완전 중복을 제거하고 pHash와 자산 관계로 근접 중복·파생본을 별도 표시한다.
3. Apple 연사 관계가 있으면 같은 묶음으로 고정한다.
4. 후보 구간 안에서 macOS Vision FeaturePrint 거리, 인물 집합과 촬영 시각 신호를 계산한다. GPS·구도 보강은 후속 평가 항목으로 둔다.
5. 단일 연결로 서로 다른 장면이 연쇄 합쳐지지 않도록 complete-link 계열 또는 작은 시간 구간의 계층적 군집화를 사용한다.
6. 정렬된 사진 ID와 알고리즘 버전을 해시해 재실행에도 안정적인 `scene_cluster_id`를 만든다.

Phase 1의 시간 기준은 일반 후보의 가장 가까운 촬영 간격 120초와 묶음 전체 시간 폭 300초다. 동일 인물·높은 시각 유사도가 유지되면 가장 가까운 촬영 간격도 최대 300초까지 허용하고, 시각 유사성이 기준을 벗어나면 120초 안에서도 다른 장면으로 분리한다. 이 값은 200~300개 장면 정답 세트에서 다시 보정한다.

Phase 1의 Vision 코사인 거리 임계값은 50장 실사진 검증을 거쳐 일반 `0.08`, 동일 인물 완화 `0.10`으로 시작한다. `0.12` 이상에서는 최대 23장이 합쳐지는 과병합이 확인되어 사용하지 않는다. 더 넓은 수동 정답 세트를 만들면 이 값을 알고리즘 버전과 함께 다시 보정한다.

### 5.3 특징 모델 비교 원칙

Phase 1은 모델 파일 의존성이 없는 macOS Vision FeaturePrint를 장면 유사도의 기준선으로 유지한다. Apple은 FeaturePrint 관측값 사이의 공식 `computeDistance` API를 이미지 유사도 비교 용도로 제공한다. 다만 현재 구현은 관측값의 `data`를 float32 벡터로 정규화한 뒤 코사인 거리를 계산하므로 공식 거리 계산 경로와 동일하다고 간주하지 않는다. Phase 1.5에서 두 거리의 순위·임계값 차이를 비교하고, 공식 API를 기본 경로로 채택할지 결정한다.

개인 취향 단계에서는 기존 `AestheticEngine`의 OpenCLIP 또는 MobileCLIP2-S0 임베딩을 다음 용도로 비교할 수 있다.

- 같은 장면 유사도
- 즐겨찾기 유형의 개인 취향 특징
- 미학 점수
- 두 번째 추천 사진의 다양성 계산

새 모델은 즉시 기본 경로에 추가하지 않는다. 같은 수동 정답 세트에서 Vision FeaturePrint 대비 장면 F1 또는 개인화 NDCG가 의미 있게 개선되고, 모델 크기·메모리·색인 시간과 라이선스 비용을 감수할 가치가 있을 때만 도입한다. MobileCLIP2-S0는 효율적인 비교 후보지만 Apple 모델 사용 조건을 제품 배포 전에 별도로 검토해야 한다.

모든 21,786장에 768차원 float16 임베딩을 저장한다고 가정하면 순수 벡터 크기는 약 31.9MiB다. 이 수치는 768차원 모델을 선택했을 때의 예시이며, 실제 차원·자료형·모델 버전에 따라 다시 계산한다. float32 특징을 float16으로 줄일 때는 장면 거리와 추천 순위의 오차도 함께 검증한다. SQLite 인덱스와 메타데이터를 포함해도 로컬 캐시로 관리 가능한 수준이지만, 첫 전체 색인은 오래 걸릴 수 있으므로 현재 분류 범위부터 계산하고 나머지는 유휴 시간에 점진적으로 채운다.

## 6. 묶음마다 최대 2장 선택

### 6.1 1차 후보 압축

묶음의 모든 사진에 비용이 큰 VLM을 호출하지 않는다. 모든 사진에 가벼운 기술·얼굴 품질을 계산해 상위 4장 정도만 상세 분석 후보로 남긴다.

가벼운 점수에는 다음을 포함한다.

- 초점과 흔들림
- 노출, 하이라이트·그림자 손실, 노이즈
- 해상도와 얼굴 영역 선명도
- 눈 감김과 심한 가림 여부
- 얼굴 크기, 프레임 이탈, 머리 잘림
- 주요 인물 수와 구도 안정성

현재 얼굴 엔진은 얼굴 검출과 임베딩은 제공하지만 눈 감김, 얼굴별 선명도와 가림 점수는 결과 계약에 없다. Phase 1.5의 첫 개선은 Apple Vision `VNDetectFaceCaptureQualityRequest`를 사용한다. 이 요청이 제공하는 `faceCaptureQuality`는 같은 request revision에서 얼굴 촬영 품질을 상대 비교하는 단일 값으로 사용하고, 조명·선명도·중심 배치 같은 개별 원인 점수로 해석하지 않는다. 한 이미지의 얼굴 관측값을 재사용해 중복 검출을 피하고, 여러 얼굴은 평균뿐 아니라 최저 품질과 주요 얼굴 품질을 함께 보존한다.

눈 감김·시선·가림 판단은 얼굴 촬영 품질만으로 부족한 사례가 수동 평가에서 확인될 때 Vision 얼굴 랜드마크를 별도 `FaceQualityEngine`에 추가한다. MediaPipe나 외부 모델은 native Vision으로 목표를 달성하지 못한 뒤 비교한다.

지원되는 macOS에서는 Swift API의 `CalculateImageAestheticsScoresRequest`를 선택적 보조 신호로 실험한다. 현재 Python 런타임에서는 `Vision.VNCalculateImageAestheticsScoresRequest`와 `VNImageAestheticsScoresObservation`으로 노출되는 것을 확인했다. 전체 미학 점수와 `isUtility`가 기술적으로 정상인 기록용 사진과 기억에 남을 추천 사진을 구분하는 데 실제로 도움이 되는지 검증한다. API 가용성과 지원 revision을 실행 시 확인하고, 사용할 수 없거나 평가 이득이 없으면 기존 기술 점수와 VLM으로 폴백한다.

### 6.2 최종 품질 점수

점수는 먼저 서로 다른 의미의 축으로 보존한다.

- 기술 품질: 초점, 흔들림, 노출, 노이즈
- 얼굴 품질: 얼굴 촬영 품질, 눈·가림·프레임 이탈
- 미학·기억성: 구도, 시각적 완성도, utility 여부
- 장면 의미: 사건, 행동과 순간의 의미
- 개인 취향: 명시적 선택과 장기 관심 패턴

초기 기준선은 설명 가능한 구조로 시작하되 각 원점수를 결과와 평가 데이터에 별도로 저장한다.

```text
묶음 내 기본 점수
  = 기술 품질 40%
  + 얼굴 품질 25%
  + 미학·구도 20%
  + 장면 의미 15%
```

인물이 없는 풍경 사진에는 얼굴 품질 비중을 0으로 두고 나머지 점수를 다시 정규화한다. 인물·풍경·음식·문서 등 유형별 점수 분포도 따로 보정해 특정 유형이 구조적으로 낮은 점수를 받지 않게 한다.

첫 번째 추천은 묶음 내 기본 점수가 가장 높은 사진으로 정한다. 두 번째 추천은 단순 2등이 아니라 다음을 함께 본다.

- 첫 번째보다 표정, 시선, 구도 또는 순간이 의미 있게 다른가
- 첫 번째와 시각적으로 거의 동일하지 않은가
- 최소 기술 품질을 통과하는가
- 개인 취향 점수가 기본 품질 차이를 뒤집을 만큼 과도하게 작동하지 않는가

이를 위해 두 번째 선택에는 첫 번째와의 유사도 패널티를 적용한다. 기준을 통과하는 후보가 없으면 두 번째를 억지로 채우지 않는다.

### 6.3 추천 상태

| 묶음 결과 | 표시 |
| --- | --- |
| 품질 기준을 통과한 사진 1장 | 추천 1장 |
| 서로 다른 장점이 있는 우수 사진 2장 이상 | 추천 2장 |
| 첫 사진과 거의 동일한 후보뿐 | 추천 1장, 나머지는 같은 장면 대안 |
| 전체가 흐리거나 실패 | 추천 0장, 검토 필요 |

전체 결과에서 `추천` 수는 점수 임계값으로 다시 증가시키지 않는다. `recommended_in_cluster`가 추천 상태의 단일 기준이 되어야 한다.

## 7. 즐겨찾기 기반 개인 취향 학습

### 7.1 학습 신호 강도

| 신호 | 해석 | 강도 |
| --- | --- | --- |
| 앱에서 사용자가 직접 `추천 유지` | 현재 목적에 맞는 명시적 선택 | 매우 강한 양성 |
| Apple 사진 즐겨찾기 | 장기적인 관심·추억·인물 선호 | 관심도 모델의 강한 양성 |
| 연사에서 사용자 선택 | 같은 순간 안의 상대적 선호 | 강한 쌍대 비교 |
| 편집 이력 | 관심을 갖고 손본 사진일 가능성 | 약한 양성 |
| 특정 수동 앨범 포함 | 앨범 의미를 확인할 수 있을 때만 사용 | 선택적 약한 양성 |
| 즐겨찾기 아님 | 싫어함을 의미하지 않음 | 미표기 |
| 앱에서 `덜 추천` 또는 명시적 제외 | 직접적인 부정 피드백 | 강한 음성 |

편집 이력은 노출 보정으로 사진을 살리려 한 경우도 있으므로 즐겨찾기와 같은 강도로 사용하지 않는다. 자동 생성 앨범, 공유 앨범과 가져오기 앨범은 취향 라벨에서 제외한다.

### 7.2 권장 모델

현재 표본 규모에서는 개인 사진으로 신경망 전체를 새로 학습하지 않는다. 이미 학습된 시각 모델의 임베딩과 구조화 특징 위에 작은 로컬 재정렬 모델을 학습하는 것이 적합하다.

```text
고정 특징
  CLIP 이미지 임베딩
  기술·얼굴·미학 점수
  사진 유형, 인물 수, 촬영 시간대
  구도·색감 특징

작은 개인 모델
  L2 정규화 선형 모델 또는 작은 pairwise ranker
```

두 학습 목적은 하나의 모델이나 손실로 바로 합치지 않는다.

1. **묶음 내 쌍대 모델**: 사용자가 앱에서 선택한 대체 사진, 연사 선택과 추천 유지 신호를 사용해 같은 장면 안의 베스트 사진을 학습한다.
2. **PU 관심도 모델**: 즐겨찾기를 양성, 나머지를 미표기로 취급해 어떤 인물·장소·행사·사진 유형을 중요하게 여기는지 학습한다.

같은 장면의 직접 선택 쌍은 배경과 사건을 통제한 상태에서 표정, 초점과 구도 차이를 배우므로 무작위 사진 간 비교보다 가치가 높다. 반대로 즐겨찾기만으로 같은 장면의 품질 우열을 추정하면 특정 인물·행사와 촬영 시기의 편향을 품질로 오해할 수 있다.

### 7.3 개인화 점수의 안전한 혼합

개인 취향은 기술 품질을 대체하지 않고 제한된 재정렬 보정값으로만 사용한다.

```text
최종 점수 = 기본 품질 점수 + 신뢰도에 따라 제한된 개인화 보정
```

- 첫 활성화 개인화 보정은 최종 100점 기준 최대 `±5점`으로 제한하고, 독립 검증 후에만 최대 `±10점`까지 확장한다.
- 흐림, 눈 감김, 심한 노출 실패 같은 하드 품질 조건은 개인화로 통과시킬 수 없다.
- 즐겨찾기 표본이 부족한 유형은 기본 모델만 사용한다.
- 모델 신뢰도가 낮거나 평가 성능이 기준선보다 낮으면 개인화 보정을 0으로 만든다.
- 개인화 적용 여부와 영향을 결과에 기록하되 민감한 학습 라벨은 노출하지 않는다.

## 8. 편향과 오학습 방지

현재 즐겨찾기는 전체의 2.23%로 불균형하고, 과거에 자주 촬영한 특정 인물·시기·카메라가 과대표현될 수 있다.

- 사진 단위 무작위 분할을 사용하지 않고 `scene_cluster_id` 단위로 학습·검증을 분리한다.
- 시간 누수를 막기 위해 최신 기간을 최종 검증 세트로 남긴다.
- 인물, 풍경, 음식, 반려동물, 문서 등 사진 유형별 지표를 따로 계산한다.
- 인물 이름을 직접 특징으로 쓰지 않고 필요하면 로컬 비가역 ID와 인물 수·관계 특징만 사용한다.
- 특정 인물의 빈도가 높다는 이유만으로 품질이 낮은 사진을 추천하지 못하게 기술 품질 하한을 유지한다.
- 최근 취향이 바뀔 수 있으므로 오래된 신호를 약하게 하고 사용자가 모델을 초기화할 수 있게 한다.
- 편집 이력과 즐겨찾기를 분리해 각 신호를 제거했을 때의 ablation 결과를 확인한다.

## 9. 저장 구조와 개인정보

개인 취향 학습은 Mac mini 안에서만 수행한다. Linux VLM에는 개인 라벨, 사람 이름, 전체 임베딩 색인과 모델 파라미터를 보내지 않는다. Linux는 최종 후보의 장면 설명이 필요할 때 최소 해상도 이미지에 대해서만 기존 정책대로 사용할 수 있다.

권장 내부 저장 구조는 다음과 같다.

| 저장소 | 내용 |
| --- | --- |
| `photo_preference_features` | 자산 ID, 특징 schema 버전, float16 임베딩, 기술 특징 |
| `photo_preference_labels` | 즐겨찾기·편집·연사 선택·앱 피드백과 관측 시각 |
| `scene_cluster_members` | 알고리즘 버전, 묶음 ID, 사진 ID, 묶음 내 거리 |
| `preference_models` | 학습 스냅샷 hash, 모델 버전, 평가 지표, 활성 여부 |

저장 위치는 Git 저장소나 일반 로그가 아니라 사용자 전용 Application Support 하위로 둔다. 디렉터리와 DB는 현재 사용자만 읽을 수 있게 만들고 다음 기능을 제공한다.

- 개인 취향 학습 끄기
- 학습 데이터 집계 보기
- 특징 캐시만 재생성
- 개인 모델과 피드백 전체 삭제
- 기본 추천 결과와 개인화 결과 비교

원본 사진, 얼굴 crop, 사람 이름과 GPS는 학습 DB에 복제하지 않는다. 로그에는 사진 ID, 임베딩, 즐겨찾기 여부를 기본적으로 기록하지 않는다.

## 10. 실행 파이프라인 변경안

```text
Apple 사진 읽기
  -> 메타데이터·연사·즐겨찾기 신호 정규화
  -> 모든 후보의 가벼운 기술·얼굴 촬영 품질 계산
  -> 완전 중복 제거 + 근접 중복·파생본 연결
  -> 시간 + 시각 + 인물 신호로 장면 묶음 생성
  -> 묶음별 상세 후보 최대 4장
  -> 미학/VLM 상세 분석
  -> 묶음별 최대 2장 선택
  -> 장면 내부 직접 피드백 모델로 제한적 재정렬
  -> 장면 간 PU 관심도 모델로 제한적 보정
  -> 결과와 선택 근거 저장
```

VLM은 전체 사진의 개인 취향을 학습하는 주체가 아니다. 묶음 경계와 개인 선호는 로컬 수치 특징으로 처리하고, VLM은 후보의 장면 의미와 설명을 보강하는 역할로 제한한다. 이렇게 해야 Linux가 꺼져 있어도 기본 유사 장면 정리와 개인화 점수를 계산할 수 있다.

## 11. 결과 화면 개선안

현재 연속 스크롤 갤러리와 우측 Inspector 구조는 유지한다. 결과 표시만 장면 중심으로 보강한다.

- 묶음 상단에 `같은 장면 8장 · 추천 2장`을 표시한다.
- 기본 갤러리에는 추천 사진을 먼저 보여주고 나머지는 `같은 장면 대안 6장`으로 접는다.
- 전체 필터에서는 모든 사진을 볼 수 있게 해 결과 누락으로 오해하지 않게 한다.
- Inspector에는 `8장 중 1위`, 선명도, 표정, 구도와 개인 취향 반영 여부를 표시한다.
- 추천 2장을 나란히 비교할 수 있는 선택적 비교 화면을 후속 제공한다.
- 사용자가 `추천 유지`, `다른 사진 선택`, `덜 추천`을 명시하면 다음 개인 모델의 강한 피드백으로 저장한다.

개인화 설명은 `내 즐겨찾기와 비슷함` 정도로 제한하지 않고 가능한 근거를 함께 보여준다.

```text
같은 장면 8장 중 1위
인물 초점과 표정이 가장 안정적입니다.
개인 취향 보정 +4점 · 밝은 야외 인물 사진 선호와 유사
```

## 12. 평가 설계

### 12.1 장면 묶음 평가

실제 보관함에서 개인정보를 외부로 내보내지 않고 200~300개 후보 묶음을 로컬 검토 세트로 만든다.

- 같은 장면 여부 경계 정답
- 사람이 고른 최상위 1장과 허용 가능한 상위 2장
- 두 번째 사진이 필요한지 여부
- 눈 감김, 흐림, 노출 실패와 구도 실패 이유

핵심 지표는 다음과 같다.

- 장면 묶음 precision, recall, F1
- 서로 다른 장면을 합친 과병합률
- 같은 장면을 나눈 과분할률
- 사람 선택 기준 Top-1 정확도
- 상세 후보 4장 안에 사람이 고른 베스트 사진이 남는 Recall@4
- 수동 상위 2장에 대한 Recall@2와 NDCG@2
- 한 묶음에서 추천이 2장을 초과한 비율, 목표 0%
- 기존 대비 반복 추천 감소율

### 12.2 개인화 평가

- 묶음 단위 및 시간 순서 분할
- 즐겨찾기 holdout Recall@K와 NDCG@K
- 같은 장면 안 pairwise accuracy
- 기본 점수 대비 개인화 uplift
- 사진 유형별 성능과 최저 성능 유형
- 기술 품질 하락량과 하드 실패 추천 수
- 모델 신뢰도와 실제 정답률의 calibration

개인화는 다음 초기 기준을 모두 만족할 때만 기본 추천에 반영한다. 수치는 외부의 보편 기준이 아니라 이 보관함에서 조정할 **초기 제품 게이트**다.

- 후보 Recall@4가 `98%` 이상이고 장면당 추천 상한 위반이 0건임
- 기본 모델보다 holdout NDCG@2가 `3~5%` 이상 개선되고 bootstrap 신뢰구간이 0을 넘음
- 하드 품질 실패 추천 수가 증가하지 않음
- 특정 사진 유형의 성능이 크게 하락하지 않음
- 다른 시점의 검증 세트에서도 개선 방향이 유지됨
- 사람이 검토한 경계 사례에서 과병합이 허용 범위를 넘지 않음

기준을 통과하지 못하면 모델 파일은 저장하더라도 `shadow` 상태로 유지하고 실제 추천에는 사용하지 않는다.

## 13. 단계별 구현 권장 순서

### Phase 0. 기준선과 데이터 계약 (부분 미완료)

사용자에게 보이는 반복 추천 문제를 먼저 막기 위해 Phase 1을 선행 구현했다. 아래 데이터 계약과 개인정보 기준선 작업은 Phase 2 전에 완료한다.

- 즐겨찾기, 연사, 편집 메타데이터를 내부 `PhotoAsset` 계약에 추가한다.
- 현재 반복 추천 수, 묶음당 추천 수와 수동 Top-2 기준선을 측정한다.
- 학습 데이터와 로그의 개인정보 제외 규칙을 테스트로 고정한다.

### Phase 1. 개인화 없는 묶음별 최대 2장

- [완료] pHash 근접 중복 대표를 입력 첫 사진이 아니라 품질 최고 사진으로 변경했다.
- [완료] 시간과 macOS Vision 특징 기반 장면 클러스터를 추가했다.
- [완료] 묶음별 상세 후보 압축과 최대 2장 선택을 구현했다.
- [완료] UI에 묶음 크기, 묶음 내 순위와 대안 사진을 표시했다.

이 단계만으로 현재 보이는 반복 추천 문제를 직접 해결할 수 있다.

### Phase 1.5. 품질·평가 기반 강화

- checksum 완전 중복과 pHash 근접 중복을 분리한다.
- 특징 캐시 키에 백엔드, Vision request revision, macOS 및 알고리즘 버전을 포함한다.
- 16×16 RGB 폴백에 Vision 거리 임계값을 재사용하지 않는다.
- 현재 raw FeaturePrint 코사인 거리와 Apple 공식 FeaturePrint 거리를 같은 정답 세트에서 비교하고, 선택한 거리 방식과 임계값을 알고리즘 버전에 고정한다.
- `VNDetectFaceCaptureQualityRequest`를 후보 압축 점수에 추가한다.
- 지원 환경에서 Vision 미학 점수의 효과와 폴백을 검증한다.
- 가족, 풍경, 실내, 음식, 야간, 연사, 편집본과 스크린샷을 포함한 200~300개 장면 정답 세트를 만든다.
- 장면 경계, 베스트 1·2장, 두 번째 추천 필요 여부와 실패 이유를 라벨링한다.
- 장면 F1, 과병합·과분할, Recall@4, Top-1, Recall@2와 NDCG@2를 측정한다.
- Vision FeaturePrint와 MobileCLIP2-S0를 같은 정답 세트에서 비교하되 개선이 입증되기 전에는 Vision을 유지한다.
- 얼굴이 포함된 사진의 대표 선택은 별도 [얼굴 품질 기반 대표 사진 선택 계획](10-face-quality-and-group-photo-selection-2026-08-04.md)에 따라 Apple Vision 계측부터 shadow 모드로 검증한다.

### Phase 2A. 명시적 피드백과 장면 내부 그림자 모델

- 결과 화면에 추천 유지, 다른 사진 선택과 덜 추천 피드백을 추가한다.
- 특징·라벨·알고리즘 버전이 고정된 재현 가능한 학습 스냅샷을 만든다.
- 직접 선택과 연사 선택을 사용한 작은 선형 또는 pairwise ranker를 `shadow`로 실행한다.
- 기본 결과와 가상 개인화 결과를 나란히 저장하되 UI 추천은 바꾸지 않는다.

### Phase 2B. 즐겨찾기 기반 장면 간 관심도 모델

- 21,786장 전체를 한 번에 처리하지 않고 분석한 범위부터 특징 캐시를 만든다.
- 즐겨찾기 486장을 중심으로 PU 관심도 학습 데이터 스냅샷을 만든다.
- 기본 결과와 개인화 가상 결과를 나란히 저장하되 UI 추천은 바꾸지 않는다.
- 시점·인물·행사 편향을 고려한 시간 분리 평가와 사진 유형별 편향을 보고한다.

### Phase 3. 제한적 개인화 활성화

- 검증 기준을 통과한 모델만 우선 최대 `±5점` 보정으로 활성화하고, 충분한 운영 검증 후 `±10점` 이내에서 재조정한다.
- 결과에 개인화 적용 여부와 설명을 표시한다.
- 설정에서 기본 추천과 개인 추천을 즉시 전환할 수 있게 한다.

### Phase 4. 지속 학습과 모델 운영

- 새 피드백이 일정 수 쌓였을 때만 재학습한다.
- 모델 버전 비교, 롤백과 개인 데이터 삭제를 제공한다.

## 14. 예상 코드 구조

| 모듈 | 책임 |
| --- | --- |
| `preference_metadata.py` | Apple 즐겨찾기·연사·편집 신호 정규화 |
| `visual_feature_engine.py` | Vision·선택적 CLIP 특징, 백엔드별 캐시와 revision 관리 |
| `scene_clusterer.py` | 완전·근접 중복, 연사와 일반 촬영 장면 묶음 생성 |
| `face_quality.py` | Vision 얼굴 촬영 품질, 눈, 가림, 얼굴 선명도와 프레임 품질 |
| `cluster_selector.py` | 묶음별 최대 2장과 두 번째 사진 다양성 선택 |
| `personal_ranker.py` | PU·쌍대 학습, 신뢰도와 제한적 점수 보정 |
| `preference_repository.py` | 특징, 라벨, 묶음과 모델 버전 저장 |

기존 `pipeline.py`가 이 구현을 모두 직접 소유하면 다시 큰 분기 파일이 된다. 파이프라인은 각 서비스의 실행 순서와 체크포인트만 조정하고, 군집화·선택·학습은 독립 모듈과 독립 테스트로 유지한다.

## 15. 테스트 항목

- pHash 대표가 입력 순서와 무관하게 최고 품질 사진이 되는지
- checksum 완전 중복과 pHash 근접 중복이 서로 다른 상태로 저장되는지
- Vision과 RGB 폴백 특징이 같은 캐시·임계값을 공유하지 않는지
- Vision request revision 또는 알고리즘 버전 변경 시 특징 캐시가 무효화되는지
- Apple 연사 관계가 다른 장면과 섞이지 않는지
- 같은 시각이라도 시각 특징이 다르면 다른 묶음이 되는지
- 작은 카메라 이동과 표정 변화는 같은 묶음으로 유지되는지
- 묶음당 추천 수가 항상 0~2인지
- 두 번째 추천이 첫 번째와 사실상 같은 사진이면 제외되는지
- 후보 압축 Recall@4가 기준을 만족하고 좋은 표정의 사진을 상세 분석 전에 제거하지 않는지
- 얼굴 촬영 품질과 선택적 미학 API가 지원되지 않을 때 결정적으로 폴백하는지
- 즐겨찾기가 아닌 사진을 음성 라벨로 저장하지 않는지
- 모델 학습·검증 분할 사이에 같은 장면이 누수되지 않는지
- 개인화가 기술 품질 하드 실패를 통과시키지 않는지
- 모델 성능이 기준 미달이면 자동으로 기본 점수에 fallback하는지
- 원본 경로, 사람 이름, GPS와 즐겨찾기 라벨이 로그·공개 결과·내보내기에 포함되지 않는지
- 모델과 특징 캐시 삭제 후 기본 추천이 동일하게 동작하는지

## 16. 완료 기준

- 같은 인물·배경의 연속 사진은 하나의 장면 묶음으로 표시된다.
- 한 묶음에서 추천되는 사진은 최대 2장이다.
- 두 번째 사진은 품질과 다양성 기준을 통과할 때만 추천된다.
- pHash 근접 중복 묶음의 대표 사진은 입력 순서가 아니라 품질로 결정된다.
- 완전 중복과 근접 중복이 구분되고 특징 백엔드별 임계값이 분리된다.
- 200~300개 장면 검증에서 후보 Recall@4와 장면·랭킹 지표가 기록된다.
- 즐겨찾기 학습은 비즐겨찾기를 자동 음성으로 취급하지 않는다.
- 개인화는 로컬에서만 학습되고 Linux VLM이나 로그에 개인 라벨을 보내지 않는다.
- 검증 기준을 통과하지 못한 개인 모델은 추천에 영향을 주지 않는다.
- 사용자가 개인화 모델과 특징 데이터를 확인하고 삭제할 수 있다.
- 결과에는 묶음 내 순위와 선택 이유가 설명 가능한 형태로 표시된다.

## 17. 최종 권장안

Phase 1은 이미 제품 기본 동작과 50장 실사진 검증까지 완료됐다. 다음 구현은 개인화가 아니라 **Phase 1.5 품질·평가 강화**가 되어야 한다. 즉, 완전·근접 중복을 분리하고 특징 백엔드 안전성을 확보한 뒤, native Vision 얼굴 촬영 품질과 선택적 미학 신호를 추가하고 200~300개 장면 정답 세트에서 검증한다.

그다음 사용자의 직접적인 대체 사진 선택으로 장면 내부 pairwise ranker를 먼저 만들고, 즐겨찾기 486장은 별도의 장면 간 PU 관심도 모델에 사용한다. 두 모델 모두 `shadow` 평가에서 기본 추천보다 실제로 좋아졌을 때만 작은 보정값으로 활성화한다. 이 순서가 반복 추천을 줄이면서도 과거 즐겨찾기의 인물·행사·시점 편향을 사진 품질로 오해하는 위험을 가장 낮춘다.
