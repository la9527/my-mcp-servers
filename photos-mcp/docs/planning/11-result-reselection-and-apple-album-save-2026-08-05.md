# 결과 재선택 및 Apple 사진 앨범 보관 계획

- 작성일: 2026-08-05
- 상태: 구현 전 검토 완료
- 대상: `PhotosMcp.app` 결과 갤러리와 Apple 사진 write-back

## 1. 결정

결과 갤러리는 `추천`과 `검토 필요`만 남긴다. `보관`은 물리적으로 사진이나 앨범을 저장한다는 뜻처럼 보이지만, 기존 구현에서는 단지 점수 65점 이상의 미선택 사진이라는 UI 전용 분류였다. 실제 보관은 사용자가 결과를 다시 고른 뒤 Apple 사진 앨범에 추가하는 명시적 쓰기 작업으로 분리한다.

같은 장면의 추천되지 않은 사진은 별도 탭으로 만들지 않고 카드에 `같은 장면 대안 · N장 중 M위`로 표시한다. 이 사진도 사용자가 직접 선택하면 앨범 보관 대상이 될 수 있다.

## 2. 현재 가능한 기능

현재 backend는 Apple 사진 원본을 복제하거나 이동하지 않고 앨범 참조만 추가한다.

| 사용 목적 | 현재 action | 현재 동작 |
| --- | --- | --- |
| 자동 추천 전체 보관 | `photos_write(action="add_selected_to_album")` | 분석 run에서 `selected=true`인 사진을 하나의 앨범에 추가한다. |
| 사용자가 고른 임의 사진 보관 | `photos_write(action="add_photo_ids_to_album")` | 전달한 Apple 사진 ID만 하나의 앨범에 추가한다. |
| 기존 앨범 사용 | 위 두 action의 `target_album_name` | 같은 이름의 앨범이 있으면 그 앨범에 추가한다. |
| 새 앨범 생성 | 위 두 action의 `target_album_name` | 같은 이름의 앨범이 없으면 새 앨범을 만들고 추가한다. |

모든 write action은 15분 유효 승인 토큰, idempotency key, 실행 영수증을 사용한다. 따라서 결과 화면에서 버튼을 누르는 것만으로 Apple 사진이 바뀌지 않으며, 최종 계획 확인 뒤에만 적용된다.

## 3. UX 시나리오

### 3.1 공통: 결과 재선택

1. 결과 갤러리의 사진 카드에 체크 상태를 둔다. 기본 선택은 `추천` 사진이며, 사용자는 `검토 필요` 또는 같은 장면 대안을 추가하거나 추천을 해제할 수 있다.
2. 상단 또는 하단의 `선택한 N장 앨범에 보관` 버튼은 선택이 한 장 이상일 때만 활성화한다.
3. 버튼은 앨범 선택 시트를 연다. 이 시트는 현재 선택 장수, 추천 자동 선택 장수, 사용자가 추가한 장수를 보여주되 사진 경로나 원본 파일명은 저장하지 않는다.
4. 적용 전에는 항상 mutation plan을 표시한다. 확인 후에만 Apple 사진 자동화 권한을 사용한다.
5. 완료 후에는 추가됨/이미 존재함/실패 수, 대상 앨범, 영수증 상태를 결과 화면에 남긴다. 사진 자체는 삭제·이동·복제되지 않는다.

### 3.2 기존 앨범에 추가

1. 시트의 `기존 앨범` 탭에서 Apple 사진 앨범 목록을 검색하고 하나를 선택한다.
2. 목록에는 앨범명, 현재 사진 수, 폴더 경로와 내부 album UUID를 함께 사용한다.
3. 계획 화면은 `기존 앨범에 N장 추가`로 표시한다.
4. 이미 같은 사진이 앨범에 있으면 Apple 사진의 idempotent add 결과를 영수증에 반영한다.

권장 사용처는 여행, 아이 행사, 가족처럼 이미 관리 중인 앨범에 선별 결과를 추가하는 경우다.

### 3.3 새 앨범 생성 후 추가

1. 시트의 `새 앨범` 탭에서 이름과 선택적 폴더를 입력한다.
2. 기본 이름은 분석 범위와 날짜를 사용한 `추천 사진 · 2026-08-05` 형식으로 제안하지만, 자동 생성은 하지 않는다.
3. 이름 중복을 검사한다. 같은 위치에 기존 앨범이 있으면 `기존 앨범에 추가`로 전환하도록 안내하며, 같은 이름의 별도 앨범을 조용히 만들지 않는다.
4. 계획 화면은 `새 앨범 “이름” 생성 후 N장 추가`로 표시한다.

권장 사용처는 한 번의 분석 결과를 독립적으로 확인하거나, 특정 기간의 추천 사진을 새로 모아둘 때다.

## 4. 구현 전제와 보완점

현재 backend write contract는 `target_album_name`과 `folder`를 사용한다. 하지만 Apple 사진은 같은 이름의 앨범을 가질 수 있으므로, 결과 갤러리에서 기존 앨범을 고르는 기능은 이름만 전달하면 안 된다.

다음 확장이 선행돼야 한다.

1. `photos_write`에 선택적 `target_album_id`를 추가하고, 기존 앨범 선택은 UUID를 우선 사용한다.
2. `AlbumWriter`와 Terminal helper에 UUID 기준 album resolve를 추가한다. 새 앨범은 생성 결과의 UUID를 영수증에 남긴다.
3. 새 앨범 생성 요청은 이름·폴더 중복을 사전 점검하고, ambiguity가 있으면 승인 전 차단한다.
4. 갤러리의 체크 상태는 run별 로컬 review 상태로 저장해 창을 다시 열어도 유지한다. 이 상태는 Apple 사진을 변경하지 않는다.
5. 앨범 추가는 기존의 approval token과 idempotency receipt 경로를 그대로 사용한다.

## 5. 권장 구현 순서

1. 결과 갤러리의 `보관` 요약·필터를 제거하고, 추천/검토 필요 두 그룹으로 단순화한다.
2. 다중 선택 및 run별 선택 상태 저장을 추가한다. 이 단계에서는 Apple 사진을 변경하지 않는다.
3. Apple 앨범 목록 API에 UUID와 폴더 식별자를 노출하고, UUID 기반 기존 앨범 추가를 구현한다.
4. 앨범 선택 시트에서 기존 앨범 추가와 새 앨범 생성 두 흐름을 제공한다.
5. 승인 계획, 실행 영수증, 재시도·중복 방지 및 실기기 검증을 추가한다.

## 6. 검증 기준

- `추천`과 `검토 필요`의 합이 전체 결과 수와 항상 같다.
- 같은 장면 대안은 검토 필요에 포함되지만 카드 설명으로 식별 가능하다.
- 기존 앨범 선택은 album UUID가 같은 앨범에만 추가한다.
- 새 앨범 이름 충돌은 사용자에게 명시적으로 선택하게 하며, 암묵적 중복 생성이 없다.
- 승인 전 Apple 사진·앨범은 변경되지 않는다.
- 승인 후 추가된 사진 수와 실패 수가 영수증과 Apple 사진 앨범 조회 결과에서 일치한다.
- 사진 원본 경로, 이미지, 개인 사진 ID는 Git 문서나 로그에 기록하지 않는다.
