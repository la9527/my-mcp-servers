# 사진 결과 갤러리와 전체 화면 뷰어 재설계 계획

- 상태: 구현 및 설치본 검증 완료
- 작성일: 2026-08-02
- 대상: `PhotosMcp.app` 사진 분류 결과 화면

## 1. 배경

현재 결과 화면은 한 페이지에 최대 6개 카드를 표시하고 `이전`과 `다음` 버튼으로 페이지를 이동한다. 분석 문장을 사진 아래에서 바로 읽을 수 있다는 장점은 있지만, 사진 수가 많을수록 전체 흐름을 훑기 어렵고 Apple 사진 앱과도 탐색 방식이 다르다.

현재 구현은 선택, 페이지 변경, 창 크기 변경 때 결과 영역을 통째로 다시 구성한다. 이 구조 위에 스크롤과 확대 기능만 추가하면 스크롤 위치 손실, 불필요한 이미지 재디코딩, 선택 상태 깜빡임이 생길 가능성이 높다. 따라서 페이지 UI를 제거하는 것뿐 아니라 결과 표시 계층을 재사용 가능한 갤러리 구조로 바꾸는 작업이 필요하다.

## 2. 결정 요약

| 항목 | 결정 |
| --- | --- |
| 결과 탐색 | 페이지 이동을 제거하고 세로 연속 스크롤로 전환 |
| 갤러리 | `NSCollectionView`와 `NSCollectionViewFlowLayout` 사용 |
| 열 배치 | 화면 비율과 실제 갤러리 폭에 따라 3~6열을 자동 계산 |
| 확대 의미 | `-`와 `+`는 열 수가 아니라 선호 카드 크기를 조절 |
| 카드 정보 | 사진 아래의 판정, 점수, 분석 문장을 유지 |
| 상세 패널 | 현재 우측 Inspector를 유지해 선택 사진의 큰 미리보기와 분석 정보 표시 |
| 사진 열기 | 카드 한 번 클릭으로 별도 전체 화면 뷰어 열기 |
| 뷰어 | macOS Quartz의 `IKImageView` 기반으로 구현 |
| 외부 라이브러리 | 추가하지 않고 macOS 기본 프레임워크 우선 사용 |
| 원본 안전성 | 갤러리는 미리보기, 뷰어는 검증된 고해상도 읽기 전용 자산 사용 |

## 3. 목표 UX

```text
┌ 사진 분석 완료 ────────────────────────────────────────────────────────┐
│ 50장 · 추천 16 · 보관 0 · 검토 필요 34                                  │
│ [전체 50] [추천 16] [보관 0] [검토 필요 34]          [−] 자동 4열 [+] │
├──────────────────────────────────────────────┬──────────────────────────┤
│ ┌──────────┐ ┌──────────┐ ┌──────────┐     │ 선택 사진 큰 미리보기   │
│ │   사진   │ │   사진   │ │   사진   │     │                          │
│ ├──────────┤ ├──────────┤ ├──────────┤     │                          │
│ │추천 64   │ │추천 64   │ │검토 51   │     ├──────────────────────────┤
│ │분석 문장 │ │분석 문장 │ │분석 문장 │     │ 분석 요약                │
│ └──────────┘ └──────────┘ └──────────┘     │ 종합·품질·의미 점수      │
│                                              │ 분류                      │
│          위아래로 연속 스크롤                │ 우측 Inspector 고정       │
├──────────────────────────────────────────────┴──────────────────────────┤
│ [Finder에서 보기]                            [결과 내보내기] [닫기]     │
└─────────────────────────────────────────────────────────────────────────┘
```

상단 요약과 필터, 밀도 조절기는 고정하고 왼쪽 갤러리만 스크롤한다. 하단 작업 버튼도 고정해 사진 목록의 위치와 무관하게 접근할 수 있게 한다. 현재 우측 Inspector는 결과 창 안에 계속 고정하고, 선택 사진의 큰 미리보기와 분석 정보를 동일한 위계로 유지한다.

## 4. 연속 스크롤 갤러리

`NSScrollView` 안에 세로 방향 `NSCollectionViewFlowLayout`을 사용하는 `NSCollectionView`를 배치한다. 필터에 해당하는 모든 사진을 데이터 소스로 제공하되, 화면에 보이는 셀만 생성하고 재사용한다.

- 페이지 번호와 `이전`, `다음` 버튼을 제거한다.
- 각 셀은 미리보기, 판정, 종합 점수, 최대 두 줄 분석 문장으로 구성한다.
- 이미지 영역은 카드마다 같은 높이를 사용하고 사진 비율은 잘리지 않도록 우선 `aspectFit`으로 표시한다.
- 카드 클릭 가능 영역은 사진만이 아니라 카드 전체로 설정한다.
- 선택된 카드는 색상에만 의존하지 않는 테두리와 접근성 선택 상태를 함께 표시한다.
- 필터를 변경하면 해당 데이터만 갱신하고 유효한 선택 사진을 유지한다.
- 결과가 0개일 때는 빈 격자를 만들지 않고 원인과 다음 행동을 설명하는 빈 상태를 표시한다.

## 5. 우측 Inspector 유지

현재 결과 화면의 우측 Inspector는 목록을 넘기지 않고도 선택 사진을 크게 보고 분석 근거를 읽을 수 있으므로 제거하지 않는다. Inspector는 갤러리와 별개의 고정 영역으로 두며 왼쪽 목록을 스크롤해도 함께 움직이지 않는다.

- 큰 사진 미리보기, 분석 요약, 종합·품질·의미 점수, 분류를 현재처럼 표시한다.
- 카드 선택이 바뀌면 Inspector만 갱신하고 갤러리 전체를 다시 만들지 않는다.
- 필터 변경 뒤 기존 선택이 남아 있으면 동일 사진을 유지하고, 없으면 첫 결과를 선택한다.
- 결과가 0개이면 `선택된 사진이 없습니다` 상태와 필터 해제 안내를 표시한다.
- Inspector 미리보기를 클릭해도 같은 전체 화면 뷰어를 열 수 있게 한다.
- 전체 화면 뷰어를 닫으면 마지막 선택 사진과 갤러리 스크롤 위치를 그대로 복원한다.

Inspector 폭은 일반 창에서 전체 콘텐츠 폭의 약 28~30%를 기준으로 하고 최소 360포인트, 최대 520포인트 범위에서 조정한다. 자동 열 계산은 Inspector를 제외한 왼쪽 갤러리의 실제 폭을 기준으로 한다. Inspector는 이번 범위에서 자동으로 접거나 제거하지 않으며, 최소 창 폭은 3열 갤러리와 Inspector가 동시에 읽기 좋은 크기를 기준으로 다시 정한다.

## 6. 화면 비율 기반 자동 열 배치

열 수는 사용자가 고정하지 않고 현재 창의 화면 비율과 갤러리의 실제 사용 가능 폭으로 매번 계산한다. 계산 대상 폭에서는 우측 Inspector, 구분선, 외부 여백과 카드 사이 간격을 제외한다. 정상 지원 창 크기에서는 최소 3열, 최대 6열 범위를 사용한다.

```text
사용 가능 폭 = 콘텐츠 폭 - Inspector 폭 - 구분선 - 갤러리 좌우 여백
자동 열 수 = clamp(floor((사용 가능 폭 + 카드 간격) / (선호 카드 폭 + 카드 간격)), 3, 6)
```

갤러리 상태에는 고정 열 수 대신 `_preferred_card_width` 또는 이에 대응하는 밀도 단계를 둔다. 마지막 밀도 단계는 `NSUserDefaults`에 저장하지만 실제 열 수는 창 크기가 바뀔 때마다 다시 계산한다. 같은 밀도 설정이라도 가로로 넓은 창이나 전체 화면에서는 열이 늘고, 좁은 창에서는 열이 줄어든다.

| 조작 | 결과 |
| --- | --- |
| `-` 클릭 | 선호 카드 폭을 줄여 사진을 더 작고 촘촘하게 표시 |
| `+` 클릭 | 선호 카드 폭을 늘려 사진을 더 크고 여유 있게 표시 |
| 키보드 `⌘-` | `-` 버튼과 동일 |
| 키보드 `⌘+` | `+` 버튼과 동일 |

툴바의 중앙 표시는 고정 설정처럼 보이지 않도록 `자동 4열` 형태로 현재 계산 결과를 알려준다. 창 리사이즈로 열 수가 바뀌면 이 표시도 즉시 갱신한다. 카드 폭은 계산 후 남는 공간을 열 사이에 균등 분배해 오른쪽에 어색한 빈 공간이 남지 않게 한다.

밀도 변경이나 창 리사이즈 전에 화면 맨 위에 보이던 사진 ID를 기록하고 레이아웃 갱신 후 같은 사진을 다시 보이는 위치로 맞춘다. 이 방식으로 자동 열 수가 바뀌거나 `-`와 `+`를 눌러도 사용자가 보던 지점을 잃지 않게 한다.

## 7. 전체 화면 사진 뷰어

사진 카드를 한 번 클릭하면 Inspector의 선택을 먼저 갱신한 뒤 별도 `PhotosMcpPhotoViewerController`가 관리하는 일반 macOS 창을 연다. Inspector의 큰 미리보기를 클릭해도 같은 뷰어를 연다. 창은 크기 조절과 전체 화면을 지원하고, 기본 상태에서는 사진을 창에 맞춘다.

뷰어의 이미지 표시는 Quartz의 `IKImageView`를 사용한다. 이 구성은 별도 패키지 없이 이미지 확대, 축소, 맞춤 표시와 스크롤 처리를 제공하므로 Python/AppKit 번들에 추가되는 의존성과 배포 위험이 가장 낮다.

| 입력 | 동작 |
| --- | --- |
| 카드 한 번 클릭 | 선택 사진을 뷰어에서 열기 |
| 트랙패드 핀치 | 사진 확대와 축소 |
| 마우스 휠 또는 트랙패드 스크롤 | 확대 상태에서 사진 이동 |
| `⌘` + 휠 | 확대와 축소 보조 조작 |
| 더블 클릭 | 화면 맞춤과 100% 전환 |
| 좌우 방향키 | 현재 필터 목록의 이전·다음 사진 |
| `Esc` | 전체 화면 해제 또는 뷰어 닫기 |
| `I` | 분석 정보 영역 표시와 숨김 |

확대 범위는 초기 구현에서 `0.1x`부터 `8x`로 제한한다. 하단 정보 영역에는 현재 카드의 분석 문장, 판정, 종합·품질·의미 점수, 분류를 표시한다. 창 크기가 바뀌어도 사용자가 직접 확대했다면 확대율과 중심 위치를 보존하고, 화면 맞춤 상태일 때만 새 창 크기에 맞춰 다시 계산한다.

## 8. 고해상도 자산 전략

현재 결과 미리보기는 최대 약 512픽셀로 생성되므로 이를 전체 화면에서 확대하면 화질이 크게 저하된다. 갤러리와 전체 화면 뷰어의 자산 경로를 분리한다.

| 용도 | 자산 |
| --- | --- |
| 갤러리 셀 | 현재 생성된 512픽셀 미리보기 |
| 전체 화면 첫 표시 | 미리보기로 즉시 표시 |
| 전체 화면 최종 표시 | 검증된 로컬 원본 또는 별도 생성한 2048~4096픽셀 뷰어 자산 |

결과에 `source_photo_path`가 있더라도 UI가 직접 파일을 열지 않는다. 전용 읽기 서비스가 경로 존재 여부, 허용된 사진 보관함 범위, 파일 형식과 접근 권한을 확인한 후 파일 URL을 반환한다. 원본이 iCloud에만 있거나 로컬에서 사용할 수 없으면 비동기로 큰 미리보기를 준비하고 뷰어에 로딩·취소·실패 상태를 표시한다.

원본 경로는 화면, 내보내기 결과, 접근성 레이블에 노출하지 않는다. 이 기능은 읽기 전용이며 Apple 사진의 사진이나 앨범을 변경하지 않는다.

## 9. 상태와 코드 구조

현재 `menu_app.py`에 집중된 결과 창 구현을 다음 책임으로 나누는 방향이 적합하다.

| 모듈 | 책임 |
| --- | --- |
| `result_gallery_appkit.py` | 결과 창, 툴바, 필터, 컬렉션 뷰, 우측 Inspector, 밀도 상태 |
| `photo_viewer_appkit.py` | 전체 화면 뷰어, 확대·축소, 키보드 탐색 |
| `viewer_asset_service.py` | 미리보기와 고해상도 읽기 전용 자산 해석 |
| `menu_app.py` | 결과 컨트롤러 생성과 창 열기 연결만 유지 |

갤러리 상태에는 전체 결과, 필터, 선택 사진 ID, 선호 카드 폭, 계산된 열 수, 맨 위 가시 사진 ID를 둔다. Inspector는 동일한 선택 사진 ID를 구독한다. 셀 선택이나 창 리사이즈 때 전체 루트 뷰를 다시 만들지 않고, 컬렉션 데이터 갱신과 레이아웃 무효화 및 Inspector 내용 갱신만 수행한다.

## 10. 성능과 안정성

- 보이는 셀만 생성하고 화면 밖 셀은 재사용한다.
- 이미지 디코딩은 백그라운드 큐에서 수행하고 AppKit 뷰 반영만 메인 스레드에서 한다.
- 셀 재사용 세대 값을 비교해 늦게 도착한 이미지가 다른 카드에 표시되지 않게 한다.
- 미리보기 경로와 목표 픽셀 크기를 키로 하는 제한형 `NSCache`를 사용한다.
- 현재 화면 주변 사진은 선택적으로 미리 가져오되 전체 원본을 한꺼번에 읽지 않는다.
- 50장뿐 아니라 최대 1000장 결과에서도 목록 스크롤이 이미지 분석이나 원본 다운로드를 자동으로 시작하지 않게 한다.
- 고해상도 요청 중 뷰어를 닫거나 다른 사진으로 이동하면 이전 요청을 취소하거나 결과를 폐기한다.

## 11. 접근성

- `-`와 `+`는 각각 `사진을 작게 표시`와 `사진을 크게 표시`라는 접근성 설명을 제공한다.
- 각 카드는 `순번, 판정, 점수, 분석 요약`을 하나의 접근성 항목으로 제공한다.
- Inspector는 선택 사진의 큰 미리보기와 분석 상세를 별도의 접근성 그룹으로 제공한다.
- 색상 외에 텍스트와 테두리로 추천·보관·검토 필요 상태를 구분한다.
- VoiceOver 순서는 상단 요약, 필터, 밀도 조절, 결과 카드, 하단 작업 순서를 따른다.
- 전체 화면 뷰어는 키보드만으로 열기, 이동, 확대, 닫기가 가능해야 한다.

## 12. 구현 단계

### 1단계: 연속 갤러리

- 결과 화면을 별도 모듈로 분리한다.
- `NSCollectionView` 기반 세로 스크롤과 셀 재사용을 구현한다.
- 기존 페이지 상태와 이동 버튼을 제거한다.
- 기존 카드의 분석 텍스트와 필터를 이관한다.
- 기존 우측 Inspector를 새 갤러리 선택 상태에 연결한다.

### 2단계: 반응형 열 배치와 밀도 조절

- 갤러리 가용 폭과 선호 카드 폭에 따른 3~6열 자동 계산을 구현한다.
- `-`와 `+`로 선호 카드 폭을 조절하고 현재 자동 열 수를 표시한다.
- 창 리사이즈와 전체 화면 전환 때 열 수를 자동 갱신한다.
- 열 변경 시 현재 가시 사진 위치를 보존한다.
- 사용자의 밀도 설정을 저장하고 복원한다.

### 3단계: 전체 화면 뷰어

- `IKImageView` 기반 뷰어 창을 구현한다.
- 확대·축소, 화면 맞춤, 좌우 탐색, 정보 오버레이를 구현한다.
- 고해상도 자산 해석 서비스와 로딩·오류 상태를 연결한다.

### 4단계: 품질 검증

- 이미지 캐시와 비동기 로딩의 재사용 오류를 검사한다.
- VoiceOver와 키보드 조작을 검증한다.
- py2app 번들에서 Quartz import와 이미지 표시를 확인한다.
- 세로 비율 3열, 일반 창 4열, 넓은 창 5~6열과 전체 화면 상태를 실제 캡처해 디자인 비율을 비교한다.

## 13. 완료 기준

- 50개 이상의 결과를 `다음` 버튼 없이 위아래 스크롤로 모두 볼 수 있다.
- 창의 화면 비율과 갤러리 가용 폭에 따라 3~6열이 자동으로 계산된다.
- `-`와 `+`는 선호 카드 크기를 조절하고 실제 열 수는 자동 계산 결과로 표시된다.
- 밀도 변경, 창 리사이즈와 전체 화면 전환 후에도 보고 있던 사진 위치와 선택 상태가 유지된다.
- 필터 변경 뒤 결과 개수, 카드 내용, 선택 상태가 일치한다.
- 왼쪽 갤러리를 스크롤해도 우측 Inspector가 고정되고 선택 사진의 정보가 정확히 갱신된다.
- 전체 화면 뷰어를 닫은 뒤 Inspector 선택과 갤러리 스크롤 위치가 유지된다.
- 화면 밖 셀을 계속 새로 만들지 않고 컬렉션 셀을 재사용한다.
- 카드를 클릭하면 해당 사진이 별도 창에 표시되고 전체 화면으로 전환할 수 있다.
- 뷰어에서 핀치와 휠, 키보드로 확대·축소와 이전·다음 탐색이 가능하다.
- 고해상도 자산이 있으면 512픽셀 미리보기 대신 이를 사용한다.
- 고해상도 자산이 없거나 로드에 실패하면 빈 화면 대신 명확한 상태와 재시도 동작을 제공한다.
- 결과 탐색과 뷰어 사용은 사진 보관함과 앨범을 변경하지 않는다.
- 개발 실행과 설치된 `.app` 번들 모두에서 동일하게 동작한다.

## 15. 기술 선택 근거

`NSCollectionView`는 정렬된 데이터의 격자 표시와 보이는 항목 중심의 셀 관리를 제공하고, `NSCollectionViewFlowLayout`은 항목 크기와 간격을 바꿀 수 있는 세로 격자에 적합하다. `NSScrollView`는 AppKit의 기본 스크롤과 확대 기능을 제공한다. `IKImageView`는 단일 이미지의 효율적인 표시와 확대, 축소, 회전 같은 기능을 제공해 별도 이미지 뷰어 라이브러리보다 현재 Python/AppKit 구조에 잘 맞는다.

Quick Look은 파일 미리보기에는 적합하지만 분석 정보 오버레이, 현재 필터 목록 탐색, 확대 조작을 제품 UX에 맞게 제어하기 어렵다. 외부 갤러리 라이브러리는 Swift 중심 래퍼와 py2app 패키징 비용이 추가되는 반면 이번 요구는 macOS 기본 프레임워크로 충족할 수 있으므로 도입하지 않는다.

## 16. 구현 및 검증 결과

2026-08-02에 계획을 다음 구조로 구현했다.

- `result_gallery_appkit.py`: 페이지 이동을 제거한 `NSCollectionView` 연속 스크롤 갤러리, 화면 폭 기반 3~6열 자동 계산, 밀도 조절, 필터, 고정 Inspector를 담당한다.
- `photo_viewer_appkit.py`: `IKImageView` 기반 전체 화면 뷰어, 화면 맞춤, 100%, 확대·축소, 이전·다음, 정보 표시를 담당한다.
- `viewer_asset_service.py`: 공개 결과에는 원본 경로를 노출하지 않으면서 로컬 작업 산출물에서 검증된 원본을 메모리에서만 연결한다.
- 직접 분류 최대 분석 수를 100장에서 1000장으로 확장하고 선택 항목을 `10, 25, 50, 100, 250, 500, 1000`장으로 구성했다.
- 결과 컨트롤러가 UI에 올리는 항목도 최대 1000장으로 제한해 잘못된 대형 결과가 무제한으로 렌더링되지 않게 했다.

실제 설치본 `/Volumes/ExtData/system/Applications/PhotosMcp.app`을 Computer Use로 조작해 다음을 확인했다.

| 검증 항목 | 결과 |
| --- | --- |
| 일반 창 자동 배치 | 기본 밀도에서 자동 3열 |
| 전체 화면 자동 배치 | 같은 밀도에서 화면 폭에 따라 자동 5열 |
| 밀도 축소 | 전체 화면에서 자동 6열까지 증가 |
| 밀도 확대 | 6열에서 5열로 복원, 선택과 Inspector 유지 |
| 연속 스크롤 | 페이지 버튼 없이 단일 세로 스크롤 영역 사용 |
| Inspector | 갤러리와 별도 고정 영역으로 유지 |
| 원본 뷰어 | `원본 화질` 표시, 전체 화면, 확대·축소, 이전·다음 동작 |
| 최대 분석 수 | 분류 화면 팝업에 `1000장` 노출 |
| 번들 | 코드 서명, `--health`, `--runtime-import-smoke`, `--vendor-runtime-smoke` 통과 |
| 회귀 테스트 | 전체 소스 테스트 293개 통과 |

컬럼 수는 고정 사용자 설정이 아니라 현재 갤러리의 실제 폭과 선호 카드 크기를 함께 사용해 계산한다. 따라서 같은 창에서도 Inspector 폭과 여백을 제외한 남은 공간에 따라 3~6열 안에서 달라지며, `-`와 `+`는 열 수를 직접 지정하지 않고 사진 카드의 선호 크기만 조절한다.
