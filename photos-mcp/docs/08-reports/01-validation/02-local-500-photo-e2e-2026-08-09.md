# 로컬 사진 500장 E2E 검증

## 범위

- 입력: SONY SD 카드 `DCIM`에서 균등 추출한 500장, 29개 폴더
- 형식: SONY ARW 478장, JPEG 22장
- 실행: 로컬 선택, 백그라운드 분류, 개별/전체 선택, 승인 기반 원본 내보내기
- 출력: `/Volumes/ExtData/PictureCategoryTest/2026-08-09-local-e2e-500`

## 결과

| 항목 | 결과 |
| --- | --- |
| 입력 로드 | 500/500 성공 |
| 결과 갤러리 항목 | 500개 |
| 1차 분석 | 18.01초 |
| 중복 감지 | 119장 |
| 상세 VLM 분석 | 426장, 2,450.37초 |
| 전체 분류 시간 | 2,471.49초 (약 41분) |
| 전체 선택 | 500/500 성공 |

분류 결과는 birthday 17, celebration 15, daily 118, meal 12, other 76, outdoor 101, portrait 14, travel 147로 기록됐다. 내보낸 약 17GB 원본은 `추천` 또는 `검토-필요`/이벤트/촬영월 구조와 점수 포함 파일명으로 저장됐으며, 각 XMP에는 `PhotosMcp`, 선택 상태, 원본 SHA-256, 내보낸 파일 SHA-256가 기록됐다.

## 판정과 후속 조치

- 로컬 ARW/JPEG 입력, Linux Qwen3.6 VLM 온디맨드 기동, 승인 토큰, 복사형 내보내기와 메타데이터 무결성은 통과했다.
- 최초 실행 당시 일반 분류는 절대 80점 기준을 공유해 최고 점수 69.21점임에도 추천 0건으로 기록됐다. 이는 분석 실패가 아니라 정책 설계의 한계였다.
- 후속 수정에서 일반 `사진 분류`는 다중 사진 장면별 상대 순위 1·2위를 추천하는 정책으로 분리했다. 같은 완료 작업을 재실행 없이 보정한 결과, 다중 사진 장면 49개에서 추천 98건으로 갱신됐다. 전체 품질 백분위 기준은 `우수 사진 선별` 모드에만 유지한다.
- 실행 시작 시 얼굴 분석 백엔드가 없어 얼굴 신호가 비활성화됐다. MediaPipe 1.0.0과 BlazeFace 모델을 개발 런타임에 설치해 초기화까지 재검증했고, `all` 설치에도 포함했다. 현재 `py2app`은 MediaPipe 네이티브 라이브러리의 Mach-O 재배치 한계로 번들 포함에 실패하므로, 설치본에서는 얼굴 분석이 선택 기능으로 비활성화된다. 얼굴이 없는 단일 검증 사진은 0건으로 정상 반환됐다.

원본별 상세 경로와 개인 사진 식별 정보는 테스트 출력의 `input-manifest.json`, `e2e-report.json`, 내보내기 매니페스트에만 보관하며 Git 문서에는 기록하지 않는다.
