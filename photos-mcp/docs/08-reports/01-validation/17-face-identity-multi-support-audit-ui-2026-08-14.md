# 복수 지지 병합 private audit UI 검증

## 결론

복수 지지 constrained grouping이 자동으로 합치려는 얼굴을 사람이 직접 확인하는 전용 private audit 흐름을 구현했다.

- 1,000장 작업의 116개 검토 장면에서 복수 지지 병합 후보 30개를 찾았다.
- 원본 해상도 얼굴 crop을 실제 생성한 뒤 판독 품질이 부족한 후보 13개를 제외했다.
- 남은 17개 병합을 얼굴 A/B 쌍으로 검토할 수 있다.
- 결과 화면에서 `복수 지지 검토`로 진입하며 숫자 `1`~`4`와 좌우 화살표를 지원한다.
- 라벨과 얼굴 crop은 `~/.photos-mcp` 아래에만 저장하고 Git에는 집계만 남긴다.
- 추천 순위, 장면 grouping, Apple 사진과 운영 DB는 변경하지 않았다.

## 검토 큐

| 항목 | 결과 |
| --- | ---: |
| 복수 지지 병합 후보 | 30 |
| 판독 불가 crop으로 제외 | 13 |
| 검토 가능한 병합 | 17 |
| 검토 pair | 17 |
| 현재 완료 | 0 |

후보와 최종 큐의 차이는 앱과 CLI 모두 같은 원본 사진 경로를 사용해 계산한다. 표시용 preview만 전달하던 초기 연결에서는 10건으로 축소되는 문제가 있었지만, private 결과 뷰어가 이미 보유한 원본 경로를 검토 기능 내부에서만 사용하도록 수정해 `17건`으로 일치시켰다. 원본 경로는 결과 JSON이나 집계 보고서로 내보내지 않는다.

## UI 검증

standalone 앱을 운영 설치 경로와 분리된 `/tmp` 경로에 빌드해 실제 화면을 확인했다.

1. 최근 작업에서 1,000장 결과를 연다.
2. 결과 화면 하단의 `복수 지지 검토` 버튼이 활성화된다.
3. 검토 창 제목은 `복수 지지 병합 검토`로 표시된다.
4. 첫 화면에 `얼굴 쌍 1 / 17 · 완료 0 · 남음 17`이 표시된다.
5. 양쪽 얼굴 crop과 `원본 사진 보기`, 네 가지 판단 버튼이 정상 노출된다.

라벨은 다음 네 가지다.

| 키 | 의미 |
| --- | --- |
| `1` | 같은 사람 |
| `2` | 다른 사람 |
| `3` | 판단 어려움 |
| `4` | 잘못 검출 |

## 집계

`scripts/analyze_face_identity_grouping_review.py`는 개인 식별자 없이 다음 집계만 출력한다.

- 라벨별 pair 수
- 라벨별로 대표되는 병합 수
- 평가 가능한 병합 수와 관측 오병합률
- Wilson 95% 오병합률 상한
- 전체 검토 완료 여부

17건에서 오류가 없더라도 Wilson 95% 상한은 약 18%이므로 이 검토만으로 5% 오류 한도를 통계적으로 입증할 수 없다. 이번 큐는 명백한 오병합을 차단하는 1차 audit이며, 운영 승격 전에는 독립 holdout을 추가해야 한다.

## 다음 단계

1. 17개 얼굴 쌍을 사용자가 직접 라벨링한다.
2. aggregate 분석 명령으로 오병합률과 Wilson 95% 상한을 계산한다.

4. 별도의 독립 holdout으로 표본을 늘린 뒤에만 운영 승격을 판단한다.
