# macOS 인물 관리 영구 저장소 통합 검증

- 일자: 2026-09-11 KST
- 대상: PhotosMcp macOS 앱의 `인물 관리`
- 데이터 원칙: 인물 이름, 사진 경로, 좌표는 이 보고서에 기록하지 않는다.

## 결론

맥 앱의 인물 관리 화면이 작업 기록과 `measurements-private.json` 얼굴 캐시에만 의존하던 문제를 수정했다. 이제 작업 기록을 지우거나 최근 작업에 얼굴 측정 산출물이 없어도 영구 인물 SQLite 저장소에 남은 인물은 계속 표시된다.

운영 저장소의 비식별 검증 결과는 다음과 같다.

| 항목 | 확인 값 |
|---|---:|
| 화면에 표시 가능한 영구 인물 | 3명 |
| 현재 얼굴 캐시 없이 보존된 인물 | 3명 |
| 이름 확인 대기 | 13건 |
| 기존 얼굴 연결 대기 | 37건 |
| 소유자 Story 이름 동의 | 3명 |
| 가족 공유 Story 이름 동의 | 3명 |

따라서 기존 인물 이름과 동의 정보가 삭제된 것이 아니다. 빈 화면은 맥 UI가 영구 저장소를 조회하지 않았기 때문에 발생했다.

## 변경 사항

### 영구 인물 우선 표시

- 앱 시작 시 owner-only SQLite 인물 저장소를 연다.
- 최근 얼굴 분석 결과로 만든 묶음과 영구 인물 목록을 병합한다.
- 레거시 JSON에서 마이그레이션된 동일 인물은 private hash mapping으로 판별해 한 번만 표시한다.
- 작업 산출물이 없는 영구 인물도 `사진 연결 필요` 상태로 표시한다.
- 저장소가 잠기거나 손상된 경우 앱 전체가 중단되지 않고 기존 얼굴 묶음 화면으로 안전하게 대체된다.

### 편집과 안전성

- 영구 인물의 이름은 맥 앱에서 SQLite의 versioned name state로 저장한다.
- 빈 이름 저장은 `unlabeled` 상태로 기록한다.
- 이름 변경은 `⌘Z` 실행 취소를 지원한다.
- `내 Story에 이름 표시`, `가족 공유 Story에 이름 표시` 동의를 맥 앱에서 각각 관리한다.
- 얼굴이 연결되지 않은 영구 인물은 drag/drop, 병합, 분리 대상에서 제외해 빈 face collection 접근과 잘못된 병합을 차단한다.

### 상태 안내

상단 집계는 `인물 수 · 연결된 얼굴 수 · 최근 작업 수`와 함께 이름 확인 및 기존 얼굴 연결 대기 건수를 표시한다. 얼굴 캐시가 없는 인물 상세 화면에서는 이름과 Story 동의가 보존돼 있으며 다음 인물 분석에서 얼굴 연결을 확인한다는 설명을 제공한다.

## 저장소 역할

| 저장소 | 역할 | 작업 기록 삭제 시 |
|---|---|---|
| `person-identities-private.sqlite3` | 영구 인물, 이름 버전, Story 동의, 얼굴/asset 관계 | 보존 |
| `people-private.json` | 레거시 수동 묶음과 마이그레이션 lineage | 보존 |
| 작업별 `measurements-private.json` | 일시적인 얼굴 crop·embedding 기반 화면 자료 | 삭제될 수 있음 |

이번 변경은 첫 번째 저장소를 맥 UI의 인물 목록 기준으로 연결한다. 사진 썸네일이 없는 영구 인물의 얼굴을 다시 붙이는 작업은 대기 lineage와 새 얼굴 observation이 실제로 일치할 때 별도로 진행된다. 임의 추정 연결은 하지 않는다.

## 사용자 확인

1. 메뉴 막대에서 PhotosMcp를 연다.
2. 메인 화면의 `인물 관리`를 선택한다.
3. 영구 인물 3명이 보이는지 확인한다.
4. 사진 연결이 아직 없는 인물에는 `사진 연결 필요 · 설정 보존됨`이 표시된다.
5. 인물을 선택해 이름 및 두 Story 동의 설정을 확인하거나 변경한다.

사진 썸네일이 즉시 보이지 않는 것은 이름 정보 유실이 아니라 현재 작업 산출물과 영구 인물 사이의 얼굴 lineage가 아직 확정되지 않았다는 뜻이다.
