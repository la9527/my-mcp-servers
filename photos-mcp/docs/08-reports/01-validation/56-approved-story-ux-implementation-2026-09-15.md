# 승인된 Story UX 구현 및 검증

작성일: 2026-09-15 · 상태: 구현·회귀·브라우저·설치본 배포 검증 완료

## 승인 범위

사용자의 “디자인 안으로 권장안으로 작업 진행”에 따라 5개 시안 중 다음 조합을 적용한다.

| 역할 | 선택안 | 제품 동작 |
|---|---|---|
| 기본 Story | 03 스크롤 시네마 | 일반 세로 스크롤, 장면 설명과 큰 사진, PC에서는 설명 영역 고정 |
| 선택형 테마 | 04 공간을 흐르는 사진 | Swiper Coverflow의 얕은 원근, 좌우 드래그, 중앙 사진 선택 |
| 공통 사진 뷰어 | 01 고요한 추억 | 화면에 맞춘 사진, 확대·이동, 하단 필름스트립, 전체 사진 그리드 |

02 순간의 묶음과 05 기억의 책은 승인 시안 폴더에 보존한다. 이번 릴리스에 다섯 가지 완성 테마를 제공한다고 표시하지 않는다. 공간형은 사진 평면에 원근을 주는 구현이며 사진 내부의 깊이 추정이나 인물 분리·배경 생성이 아니다.

디자인 기준은 editorial photo-first, 무채색 바탕, 낮은 장식 밀도다. design-taste-frontend 기준의 목표값은 디자인 변주 6 / 동작 4 / 정보 밀도 3으로 해석했다. 기존 Python HTML 렌더러와 Mac/Android 계약을 유지하며 프레임워크 교체는 하지 않았다.

## 화면 구조와 흐름

```text
Story 열기
  ├─ 스크롤 시네마(기본): 표지 → 날짜/장소별 장면 → 사진
  ├─ 정보와 보기 설정: 테마 선택·저장, 인물 필터, 기존 관리 기능
  └─ 공간형 선택: 장면별 중앙 사진 ← 드래그 → 다음 사진
                         │
                    사진 선택
                         ↓
              화면에 맞춘 공통 사진 뷰어
                 ├─ 더블클릭/더블탭·핀치 확대
                 ├─ 기본 배율에서 좌우 이동
                 ├─ 하단 위치 표시·주변 썸네일
                 └─ 전체 사진 그리드 → 원하는 사진
                         ↓
                  닫기/뒤로가기 → 본문 복귀
```

- 강한 녹색·컬러 패널 대신 사진 자체가 색을 만든다. 기본 테마는 OS 라이트/다크를 따르고 공간형은 어두운 배경을 사용한다.
- 사진의 종횡비를 보존하고 첫 진입은 전체 이미지가 보이는 화면 맞춤이다. 확대 상태는 다음 사진으로 넘기지 않는다.
- +/− 확대 버튼은 없으며 확대된 동안만 `화면에 맞춤`을 표시한다.
- 하단에는 현재 사진 번호와 주변 썸네일만 표시한다. 썸네일은 PC 최대 11개, 좁은 화면 최대 7개다.
- 상세 지도와 위치 목록은 장면 아래 `촬영 장소와 지도`를 열어 확인한다. 원래의 지도 URL·권한 정책은 바꾸지 않았다.
- 공유, 테마 저장 등의 기존 관리 항목은 `정보와 보기 설정`에 모아 감상 흐름과 분리한다.
- 인물 필터에 맞춰 본문·장면·뷰어 사진 목록이 함께 바뀐다. 해당 인물이 없는 장면은 숨긴다.
- Swiper는 기존 로컬 번들 14.2.0을 사용한다. CDN이 필요하지 않다. 자동 재생·자동 카메라 비행은 없다.
- 모바일은 얕은 원근을 적용한다. `prefers-reduced-motion`이면 Coverflow 대신 평면 슬라이드, 전환 시간 0을 사용한다.
- Android 시스템 바/앱의 풀스크린 정책은 변경하지 않는다. 이번 변경은 공통 Story 웹 콘텐츠에 한정한다.

## 저장·배포 호환성

- 기본 `theme_id`는 `scroll_cinema`, 선택형은 `spatial_ribbon`이다.
- 기존 5개 테마 정의는 과거 공유 스냅샷 호환용으로 보존한다. 새 테마 선택 화면에는 승인된 2개만 표시한다.
- 본인용 Story를 읽을 때 레거시 테마를 새 기본 테마로 표시한다. 원래 revision을 유지하는 읽기 전용 projection이며 저장소를 일괄 덮어쓰지 않는다.
- 기존 공개 공유 스냅샷은 테마를 유지한다. 새로 만든 공유에는 본인용 화면과 같은 테마를 기록한다. 사진 뷰어/공통 레이아웃 개선은 공통 자산으로 제공되므로 과거 공유가 픽셀 단위로 완전히 동일한 것은 아니다.
- Story 자산 버전은 10으로 올려 구버전 CSS/JS 캐시 혼용을 피한다.
- `story_experience.py`를 Python 모듈로 패키징해 소스 실행·Mac standalone·모바일 서비스가 같은 CSS/JS를 사용한다.
- 사진 원본·추천 결과·인물/GPS DB 삭제나 재분석, 신규 공개 공유는 수행하지 않았다.

## 구현 파일

- `application/story_presentation.py`: 테마 정의, 기본값, 본인용 레거시 projection
- `application/story_sharing.py`: 새 공유 테마 일관성
- `interfaces/http/story_web.py`: 의미 구조, 표지, 정보 패널, 공통 뷰어, 자산 버전
- `interfaces/http/story_experience.py`: 스타일과 Swiper/뷰어 상태 관리
- `scripts/preview_story_design.py`: 실제 Story를 읽기 전용으로 확인하는 loopback 전용 미리보기
- `scripts/check_story_browser.mjs`: 실제 브라우저 동작 회귀 검사. 테마 변경은 미리보기만 하며 저장하지 않는다.

## 검증 결과

### 자동 테스트

` .venv/bin/python -m pytest -q ` → **1,084개 통과**(최종 재검사 15.76초).

기본 테마, 레거시 호환, 새 공유, 소유자·모바일 테마 API, 권한·revision 보호, 공통 뷰어 문자열 계약을 포함한다. 자동 테스트만으로 UX를 검증했다고 간주하지 않는다.

### 실제 브라우저

운영 Story의 315장 사진을 읽기 전용으로 렌더링했다. 스크린샷은 개인 사진이 포함되어 `/tmp`에만 보관하고 저장소 문서에 복제하지 않았다.

1440×1000 / 390×844, 기본·공간형의 4개 조합에서 다음을 검증했다.

- 가로 오버플로 없음, 첫 사진 화면 맞춤
- 실제 가로 사진(2048×1536)은 1440×1000 뷰포트에서 998.7×749, 844×390에서는 322.7×242로 전체 사진 맞춤 확인
- 더블클릭 확대 및 다음 사진에서 배율 1 복귀
- 키보드 좌우 이동, 전체 사진 그리드와 마지막 사진 선택
- 실제 마우스 드래그로 다음 사진 1장 이동(PC·모바일 폭, 두 테마)
- 브라우저 뒤로가기로 뷰어만 닫힘, 뷰어 DOM 정리
- 테마를 반복 전환해도 Swiper wrapper 중첩 없음
- 인물 필터와 전체 사진 복귀 일치
- axe WCAG 2 A/AA 자동 검사 위반 0건. 접근성 전체 준수를 보증하는 결과는 아님
- 모션 감소 시 평면 전환, 사진 0장/1장 상태

검사 과정에서 발견한 실제 문제:

1. 데스크톱의 native `dblclick`이 Swiper `doubleTap` 없이 도착하는 경우 확대되지 않음 → native fallback을 추가하고 중복 이벤트 시 이중 토글을 방지.
2. 사진 클릭 후 포커스가 body로 이동하면 dialog 내부 키 처리만으로 좌우 이동이 안 됨 → 열린 뷰어 상태에 한정한 window 키 처리로 교정.
3. 모바일 공간형에서 긴 제목·메타데이터가 첫 사진을 아래로 밀음 → 공간형 표지·중복 날짜를 축소하고 첫 장면을 앞당김.
4. 큰 사진·전체 사진 영역의 ARIA label에 대응하는 role이 누락됨 → 명명된 region으로 보완하고 열린 뷰어·그리드 접근성 재검사 추가.

공간형 뒤에 native dialog를 띄운 상태에서 axe는 일부 문구의 배경 겹침 때문에 명암비를 `incomplete`로 보고했다. 실제 elementsFromPoint로 문구가 위에 있는 것을 확인하고, 적용 색상 `#f4f4f5 / #b4b5bc / #a7a8ae`와 배경 `#101113`의 명암비를 각각 17.19 / 9.24 / 7.97로 확인했다. 이 항목은 자동 판정 불가를 숨겨 0으로 보고하지 않는다. 테스트는 명암비 외의 미판정 항목을 허용하지 않는다.

### 검증 범위의 한계

- 모바일 검사는 Chromium 모바일 폭으로 수행했다. 실제 Android 하드웨어 핀치/시스템 바와 Safari/WKWebView 제스처를 새로 실기기 검증한 것은 아니다.
- 읽기 전용 미리보기는 Google 지도 API 키를 로드하지 않는다. 지도 삽입의 실제 운영 도메인 권한은 별도 운영 화면 확인 대상이다.
- CSS 원근 효과는 구현했으나 저사양 기기별 FPS를 실측하지 않았다.
- 02/05의 독립적인 UX와 애니메이션은 이번 범위에서 구현하지 않았다.

## 운영 반영

- `scripts/build_framework_standalone.sh` 최종 실행 exit 0. 생성 빌드 산출물과 기존 설치 번들은 재생성·교체했으며 사용자 사진/DB는 삭제하지 않았다.
- `/Users/byoungyoungla/Applications/PhotosMcp.app` 재설치, 코드서명 strict/deep 검사와 osxphotos·photo-ranker·인물 런타임 smoke 통과.
- 기존 분석 실행이 없음을 확인한 후 Mac 앱 재시작. 새 PID 92118, health `ok`, daemon `ready`, active jobs 0.
- `com.photosmcp.mobile-client` 서비스 재시작. 새 PID 92117, launchctl 상태 running.
- Mac localhost `/photos` 실제 브라우저: `scroll_cinema`, 사진 315장, 자산 `v=10`, 가로 오버플로 없음. 큰 사진 viewer의 화면 맞춤·Swiper·region 확인.
- 설치 앱이 제공하는 CSS/JS SHA-256과 소스의 CSS/JS가 각각 동일함을 확인했다.
- Tailscale HTTPS `/photos` 200, `/mobile-client/v1/capabilities` 200.
- localhost의 Tailnet 소유자용 capabilities는 403, 로그인 세션 없는 모바일 Story CSS는 401로 기존 인증 경계가 유지된다.
- APK 바이너리를 바꾸거나 ADB 설치를 수행하지 않았다. 기존 Android 앱에서 Story를 다시 열면 재시작된 서버의 새 웹 화면을 받는다.
- 검증 전용 브라우저 세션과 loopback 18809 미리보기 서버는 종료했다. 운영 서비스는 유지한다.

사용 방법: Story 상단 `정보와 보기 설정` → 테마 설정에서 두 방향을 미리 보고 저장. 사진 클릭은 공통 뷰어, 상단 `전체 사진`은 사진 모아보기다.
