# 기억의 책: 물리 표현 구현 및 화면 검증 기록

## 구현 범위

- 담당 모듈: `src/photos_mcp/interfaces/http/story_book.py` (`BOOK_CSS`, `BOOK_JS`).
- `window.PhotosStoryBook.mount({host, tiles, onOpen, title, intro, initialTile, compact, reduceMotion})`.
- 반환: `destroy()`, `getActiveTile()`, `getPage()`, `goToPage()`.
- 원본 타일은 읽기 전용으로 이용한다. Story, 인물, GPS 및 사진 원본을 변경하지 않는다.
- 책의 양면과 모바일 한 면에 동일한 논리 페이지를 사용한다. 장면 목차, 번호, 좌우 드래그, 방향키, 취소 가능한 드래그를 지원한다.

## 표현 방식

승인된 05번 시안의 종이 사진집을 기준으로, 종이와 책등을 제외한 조작부는 절제한다. 종이색과 출판용 명조는 시안에 따른 선택이다. 디자인 기준은 편집형 가족 사진집, 다양성 6 / 동작 7 / 밀도 3이다.

정지한 페이지는 일반 HTML이다. 따라서 글자, 사진 확대 버튼, 목차가 브라우저의 기본 접근성 경로를 그대로 이용한다. 사진은 `contain`으로 전체 비율을 보존하고, 사진과 접힘선 사이에 여백을 둔다.

책장이 움직이는 동안에만 데스크톱 32개, 모바일 22개의 작은 표면으로 종이를 구성한다. 각 표면은 독립적인 각도와 깊이를 가지며, 인접 표면 간 길이를 보존한다. 시작과 끝은 평면, 중간은 곡면이다. 표면 법선에 따라 밝기가 달라지고, 종이 밑 그림자와 책등·종이 단면을 함께 표현한다. 단순히 사각형 전체를 `rotateY`하는 방식이 아니다.

초기 HTML 복제 방식에서 사진 위에 가는 이음선이 보였다. 검토 후 움직이는 앞뒷면만 로컬 브라우저 Canvas로 표현하도록 변경했다. 실제 페이지의 측정된 글자·이미지 위치를 이용하며, 두 장의 페이지를 작은 Canvas 조각에 복사한다. 외부 업로드, `data:`/`blob:` URL 및 CSP 완화는 사용하지 않는다. 정지하면 즉시 선명한 원래 HTML 페이지로 복귀한다.

사진은 현재 펼침과 인접 펼침만 미리 준비한다. 전체 앨범 수만큼 종이 조각을 생성하지 않는다. 모션 감소 설정에서는 곡면 애니메이션 없이 즉시 페이지를 바꾼다.

## 페이지 구성

- 장면 시작: 큰 사진 한 장 / 제목·이야기·보조 사진 양면 구성.
- 나머지 사진: 사진 비율을 보존하는 1~2장 페이지.
- 긴 이야기와 제목: 별도 페이지로 나누며 모바일에서도 같은 페이지 번호를 유지한다.
- 사진을 누르면 공통 감상 뷰어를 연다. 테마를 전환할 때 현재 사진을 반환하여 위치를 이어갈 수 있다.

## 검증 이력

### 1차

실제 36장(2026-08-14)과 전체 315장으로 PC 1440×1000, 모바일 390×844를 확인했다.

- 발견: compact/reduceMotion 설정에 MediaQueryList 객체가 전달되어 PC도 한 장으로 보였다. Boolean 정규화 및 통합 호출 수정.
- 발견: 종이 질감이 사진 위까지 덮였다. 질감 레이어를 콘텐츠 뒤로 이동.
- 발견: PC 하단 조작부가 첫 화면 아래로 밀렸다. 실제 책 시작 위치에 따라 높이를 계산.
- 확인: 수정 후 PC 양면과 하단 페이지 이동이 1000px 높이에 표시된다.

### 2차

- PC 양면 및 모바일 한 면에서 사진이 잘리지 않으며 이전·다음이 표시됨.
- 실제 마우스 드래그를 잡은 채 곡면 상태를 캡처함. 종이 표면이 휘어지는 것은 확인했으나 조각 사이 이음선이 보여 Canvas 표면 방식으로 추가 개선함.
- 다른 테마 교차 검토에서 quiet/moment 사진의 원형·타원형 잘림과 spatial 제목 중복을 발견하여 해당 담당자에게 전달함.

### 3차

- PC에서 32개 조각과 앞뒷면 Canvas 64개를 실제 드래그 중 확인했다. 조각별 곡률과 종이의 앞뒷면이 보이며, 2차에서 보인 사진 위 흰 이음선이 사라졌다.
- 모바일에서도 실제 드래그 상태를 캡처했다. 사진은 종이 곡면을 따라 변형되지만 잘려 없어지는 영역이나 흰 이음선이 없다.
- 드래그 완료 후 Canvas는 0개가 되어 정지 HTML로 복귀했다. PC에서 다음 페이지로 넘어간 뒤 모바일 전환 시 같은 논리 페이지(3쪽)가 유지되었다.
- 사진 클릭으로 공통 확대 뷰어가 열리고 1536px 이미지가 로드되는 것을 확인했다. Escape 복귀와 목차 열기도 확인했다.
- axe WCAG A/AA 검사: 위반 0개. 종이 질감 pseudo-element 때문에 자동 색상 판정이 불가능한 1종의 수동 확인 항목은 남았으며, 사용한 종이/본문 대비는 별도 확인 대상이다.
- 교차 검토: quiet/moment의 원형·타원형 잘림과 spatial의 제목 중복 수정 확인. spatial의 모바일 중앙 사진이 작고 흐린 점은 별도 담당자에게 추가 개선 요청했다.

개인 사진이 포함된 실제 캡처는 저장소 밖 `/tmp/photos-review-r3-book-desktop-curl.png`, `/tmp/photos-review-r3-book-mobile-curl.png` 등에 저장했다. 이 보고서에 원본 사진을 복제하지 않는다.

### 4차: 긴 내용·작은 화면 경계 검증

`scripts/check_story_book_browser.mjs`를 추가해 실제 사진 타일을 재사용하는 브라우저 내부 fixture를 검사했다. 사진을 새로 서버에 등록하거나 DB를 수정하지 않는다.

- 해상도: 1440×1000, 390×844, 844×390, 320×568.
- 각 해상도에 1장, 2장, 혼합 9장, 긴 제목·장문과 9장 조합을 실행하여 총 16개 케이스를 검사했다.
- 최초 검사에서 긴 제목이 이어지는 페이지와 마지막 속지에 반복되어 글이 잘리는 문제를 발견했다. 이어지는 페이지의 중복 제목을 제거하고 마지막 속지에는 짧은 제목만 표시한다.
- host의 내부 padding이 책 너비에 포함되어 가로로 넘치는 문제를 발견해 실제 content width를 사용하도록 수정했다.
- 글 전용 페이지의 내용을 150자까지 묶어, 동일한 긴 제목·본문이 54쪽에서 30쪽으로 줄어들었다. 제목과 본문은 공백을 제외한 모든 글자가 순서대로 보존되는지 브라우저에서 확인했다.
- 최종 16/16 통과: 사진 누락 0건, 제목·본문 보존, 페이지 내부 영역 넘침 0건, 문서 가로 넘침 0건.
- 낮은 가로 화면에서는 페이지를 작게 압축하지 않고 세로 스크롤을 허용한다. 사진 단독 전체 화면 감상은 공통 뷰어에서 제공한다.

실제 캡처는 `/tmp/photos-book-r4-two-1440x1000.png`, `/tmp/photos-book-r4-two-844x390.png`, `/tmp/photos-book-r4-long-390x844.png` 등에 저장했다.

### 계산 및 구조 테스트

`tests/test_story_book.py`는 별도 Python 근사 계산이 아니라 실제 렌더러의 JavaScript geometry 함수를 Node에서 실행한다.

- 시작·끝 평면 위치와 각도.
- 중간 32개 서로 다른 법선과 실제 깊이.
- 전체 동작 구간에서 인접 조각 길이 보존.
- 텍스트는 HTML 주입이 아닌 `textContent`로 삽입.

초기 3개 테스트 통과. 통합 결과는 최종 검증 문서에서 합산한다. 이 문서만으로 전체 5개 테마 작업 완료를 주장하지 않는다.

## 기술 참고

StPageFlip 공식 저장소(https://github.com/Nodlik/StPageFlip)의 soft/hard page 구조를 검토했으나, 이번 요청은 조각별 곡률·표면 음영을 직접 제어해야 하므로 해당 의존성을 설치하지 않았다. 종이의 구조적 두께 및 굽힘은 웹 상의 시각적 모델이며, 실제 재료의 물성을 유한요소로 해석하는 시뮬레이터를 의미하지 않는다.
