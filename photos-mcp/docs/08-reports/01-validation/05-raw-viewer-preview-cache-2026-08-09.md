# RAW 전체 화면 뷰어 렌더링 검증

## 문제

RAW 원본을 ImageKit에 직접 전달하면 macOS ImageIO가 카메라 내장 저해상도 프리뷰를 먼저 그린 뒤 RAW 전체를 점진적으로 해제한다. 이 과정에서 한 화면 안에 선명한 영역과 계단 현상 영역이 섞였다가 잠시 뒤 복원될 수 있다.

이는 사진 분류 모델이 이미지를 손상한 것이 아니라 전체 화면 뷰어의 RAW 직접 렌더링 방식 문제다.

## 수정

- 전체 화면 뷰어는 RAW 원본을 ImageKit에 직접 전달하지 않는다.
- 첫 열람 때 ImageIO가 RAW를 `4096px` JPEG로 완전히 렌더링한다.
- 결과는 로컬 `viewer-raw` 캐시에 원자적으로 기록한 뒤, 완성된 JPEG만 뷰어에 전달한다.
- 캐시가 없을 때는 준비 상태를 보이며 저해상도 프리뷰를 확대하지 않는다.
- 분석 파이프라인의 빠른 내장 프리뷰 사용은 유지한다. 분석용 해상도 정책과 전체 화면 표시 품질을 분리했다.
- ImageKit의 URL 디코드가 첫 화면 맞춤 이후에 끝나는 경우를 위해, 즉시·120ms·450ms 뒤에 유효한 현재 사진만 자동 재배치하고 다시 그린다. 따라서 창 크기 조절이 이미지 표시를 복구하는 조건이 되지 않는다.

## 실제 ARW 검증

개인 원본 경로와 사진 식별자는 기록하지 않았다.

| 항목 | 결과 |
| --- | --- |
| RAW 전체 디코드 미리보기 | 4096 × 2731px |
| 첫 캐시 생성 | 1.16초 |
| 이후 캐시 조회 | 0.0001초 |
| 캐시 재사용 | 성공 |

설치 앱에서도 500장 결과의 RAW 첫 사진을 전체 화면으로 열어 `고해상도 RAW 미리보기를 준비하는 중` 상태가 먼저 나타나고, 약 2.5초 뒤 `고해상도 RAW 미리보기`로 전환되는 것을 확인했다. 전환 뒤 화면에는 부분적인 저해상도 확대나 계단 현상이 없었다.
