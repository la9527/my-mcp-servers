# 복수 지지 병합 audit 결과와 독립 holdout

## 결론

1,000장 작업의 복수 지지 병합 17건을 모두 직접 확인한 결과는 `같은 사람 17`, `오병합 0`이었다. 관측 오병합률은 0%지만 Wilson 95% 상한은 18.43%이므로 운영 기준 5%를 아직 충족하지 않는다.

| 항목 | 결과 |
| --- | ---: |
| 검토 완료 병합 | 17 |
| 같은 사람 | 17 |
| 다른 사람 | 0 |
| 판단 어려움 | 0 |
| 잘못 검출 | 0 |
| 관측 오병합률 | 0.00% |
| Wilson 95% 상한 | 18.43% |
| 운영 허용 상한 | 5.00% |
| 승격 가능 | 아니요 |

오류가 계속 0건이라고 가정해도 Wilson 상한을 5% 이하로 낮추려면 총 73건이 필요하다. 현재 기준으로 추가 56건이 필요하다.

## 자동 승격 게이트

집계 도구는 다음을 자동으로 출력한다.

- `audit_complete`: 모든 쌍 검토 완료 여부
- `observed_false_merge_rate`: 관측 오병합률
- `false_merge_rate_wilson_95_upper`: Wilson 95% 상한
- `additional_zero_error_merges_needed`: 추가 무오류 병합 필요 수
- `promotion_ready`: 운영 승격 가능 여부
- `blocking_reasons`: 승격 차단 사유

현재 차단 사유는 `insufficient_statistical_confidence` 하나다. 사람 라벨은 모두 완료됐고 관측 오류도 없다.

## 독립 holdout 준비

기존 1,000장 작업과 사진 ID가 겹치지 않는 저장 작업을 추가 계측했다. Linux LLM은 사용하지 않았으며 OpenCV YuNet·SFace, MediaPipe와 Apple Vision을 로컬에서만 실행했다.

| 작업 규모 | 복수 사진 장면 사진 | 얼굴 사진 | 얼굴 수 | 최종 검토쌍 |
| ---: | ---: | ---: | ---: | ---: |
| 500장 | 199 | 86 | 319 | 2 |
| 100장 | 55 | 43 | 67 | 3 |
| 50장 | 46 | 46 | 99 | 0 |
| 합계 | 300 | 175 | 485 | 5 |

50장 작업에서 검토쌍이 0건인 것은 오류가 아니라 해당 작업에 복수 지지 병합이 없다는 뜻이다. 빈 holdout도 정상 결과로 저장하도록 CLI 경계 조건을 보완했다.

독립 작업 3개의 후보는 총 9건이었고 실제 원본 crop 판독 기준에서 4건을 제외해 5건이 남았다. 이 5건은 하나의 private AppKit 검토 큐로 합쳐졌다.

### 2026-09-01 독립 holdout 완료

준비된 5쌍을 모두 사람이 확인했다. 결과는 같은 사람 5, 오병합 0, 미검토 0이며 독립 표본의 Wilson 95% 상한은 43.45%다. 사람 검토는 완료됐지만 독립 표본만으로 운영 허용 상한 5%를 입증하지 못하므로 `promotion_ready=false`를 유지한다.

기존 primary audit 17건과 참고용으로 합산하면 총 22건 무오류지만, readiness에서는 보정에 사용된 primary audit과 독립 holdout을 별도 gate로 유지한다. 독립 holdout 자체가 5% 상한을 충족하려면 오류가 추가되지 않는다는 가정에서도 총 73건, 현재보다 68건이 더 필요하다.

## 해석

복수 지지 병합은 보수적인 정책이라 일반 사진에서 발생 빈도가 낮다. 현재 독립 데이터 650장을 추가해도 검토 가능한 사건은 5건뿐이다. 따라서 단순히 무작위 사진 수를 늘리는 것보다 다음 자료를 우선 수집하는 편이 효율적이다.

1. 같은 장소에서 같은 사람이 여러 프레임에 반복 등장하는 연속 촬영 묶음
2. 같은 배경에서 사람이 교대하는 장면
3. 단체사진에서 일부 인물만 바뀌는 장면
4. 어린이 성장 사진처럼 시간 차이가 크지만 동일인인 장면

이 자료는 정책이 실제로 합치려는 경계 사례를 더 자주 만들면서 다른 사람 오병합도 함께 드러낼 수 있다.

## 개인정보와 운영 영향

- 얼굴 crop, 임베딩, 사진 ID와 경로는 `~/.photos-mcp` 아래 private 큐에만 있다.
- Git 문서에는 작업별 집계만 기록한다.
- 추천 순위, 장면 grouping과 Apple 사진은 변경하지 않았다.
- `promotion_ready=false`이므로 복수 지지 정책을 운영 추천에 적용하지 않는다.

## 다음 단계

1. 독립 holdout 5건 사람 검토와 readiness 재집계는 완료했다.
2. 인물 기반 추천을 계속 개발할 때만 서로 다른 인물 전환이 포함된 경계 장면 중심의 독립 holdout을 추가한다.
3. 독립 표본 총 73건 또는 사전에 합의한 개인용 위험 기준에 도달할 때만 운영 승격을 다시 검토한다.
4. 추가 검토를 진행하지 않으면 현행 `shadow_only`와 운영 추천 미반영 정책을 유지한다.
